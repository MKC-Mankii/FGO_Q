# FGO_Q V5 架构演进与全屏幕自适应提案 (V5 Execution Proposal)

本文档定义了 **FGO_Q v5 架构** 的核心愿景、技术基石、底层数学模型、系统模块划分与落地演进规划。

---

## 1. 架构总览与愿景演进

### 1.1 从 V4 到 V5 的代际飞跃

在 **V4 架构** 中，我们成功实现了**策略配置（Config）与执行引擎（Runner）的解耦**，确立了双向文件总线与内存热重载机制，彻底消除了日常战斗策略调优对 PC 按键助手的依赖。

然而，在面对实际多设备运行环境和游戏版本更迭时，V4 依然存在两个底层瓶颈：
1. **屏幕分辨率与长宽比硬编码绑定**：
   - 所有的找图区域 `[x1, y1, x2, y2]` 和点击坐标 `[x, y]` 全部硬编码在 `battle_v4_runner.q` 内部，基准绑定在 `1440×810 (16:9)`。
   - 一旦用户更换模拟器分辨率（如 1280×720、1920×1080）或屏幕长宽比（如全面屏 18:9、20:9，或平板 16:10），坐标全面偏离，原有找图全部失效。
2. **视觉特征图打包在静态附件包（.atc）中，维护链路冗长**：
   - 所有的匹配图片（如 `ATTACK_BTN.png`、各从者头像等）均被编译封死在 PC 助手的 `.atc` 附件中。
   - 当**游戏大版本更新 UI 微调**、**推出新活动特定结算界面**、或**上新从者/倍卡礼装**需要重新截图时，用户必须经历“外部截屏 ➔ 图像工具裁切 ➔ 打开 PC 助手 ➔ 附件管理器删旧导新 ➔ 重新打包 ➔ 重启模拟器”长达 15~30 分钟的高门槛流程。

### 1.2 V5 的核心愿景：三位一体动态资产与全屏自适应
**FGO_Q V5** 将定位为：**「全屏幕比例智能自适应 + 动态资产免打包热更平台」**。
- **仓库既有资产全量透出（基线可视）**：标定工作台直连并透出仓库内现存的历史视觉特征图库（`images/attached images/` 包含 96+ 张核心识别模板），开箱即可直接查阅与调用已有基线素材，绝不出现“有图却显示无图”的断层。
- **裁切保存“双写同步”（仓库版本替换 + 模拟器毫秒热更）**：
  - **替换库内源图**：用户在 Web 交互框选裁切后，系统自动原位替换 Git 仓库内的对应图片（`images/attached images/<fname>`），并自动归档历史快照，使得资产变更直接纳入 Git 源码版本管理。
  - **直推模拟器运行池**：同时通过 ADB 毫秒级静默推送到模拟器 `/sdcard/FGO_Q/images/`，使执行引擎即刻识别新特征，达成 0 编译、0 打包的 10 秒闭环！
- **视口黑边识别与锚点自适应系统（Viewport & Anchor System）**：基于 FGO 渲染特性建立居中视口模型与边缘吸附锚点算法，支持任意长宽比与分辨率的坐标自动推导。

## 2. 核心数学模型：游戏视口与锚点自适应算法

### 2.1 为什么线性缩放必定失败？
FGO 的画面渲染并非全屏线性拉伸。当运行在全面屏（如 18:9, 19.5:9, 21:9）或平板（16:10, 4:3）时：
- 游戏的核心战斗渲染器是基于 **16:9 核心安全区** 运行的。
- 在超宽屏下，左右两侧会出现**暗纹装饰黑边（Pillarbox）**，核心视口（Active Viewport）水平居中。
- 关键 UI 的布局规则各异：
  - **居中对齐（Center Anchor）**：发牌选卡、宝具卡、吃苹果弹窗、选人目标弹窗等，是以视口中心为基准定位的。
  - **右下吸附（Bottom-Right Anchor）**：Attack 按钮、结算界面的 Next 连续出击按钮。
  - **左下吸附（Bottom-Left Anchor）**：从者 1~3 技能栏。
  - **右上吸附（Top-Right Anchor）**：御主礼装展开按钮、战斗 Menu。
  - **左上吸附（Top-Left Anchor）**：敌方目标 1~3 序号、撤退确认。

如果直接使用 $X_{new} = X_{base} \times \frac{W_{new}}{W_{base}}$，左右黑边的存在会导致居中元素、左下元素和右下元素发生严重相位偏移，点击完全错位！

### 2.2 V5 视口与锚点数学计算公式

设基准分辨率为 $W_0 \times H_0$（标准 16:9，例如 $1440 \times 810$），当前屏幕分辨率为 $W \times H$。

#### 步骤 1：计算有效视口（Active Viewport）与黑边偏移量
FGO 保持 16:9 比例适配，则当前屏幕上的有效视口尺寸 $(V_w, V_h)$ 与偏移量 $(O_x, O_y)$ 为：
$$R_{base} = \frac{16}{9} \approx 1.7778, \quad R_{screen} = \frac{W}{H}$$

* **情况 A：宽屏全面屏 ($R_{screen} \ge R_{base}$)**
  - 垂直方向撑满：$V_h = H, \quad O_y = 0$
  - 水平有效视口：$V_w = H \times R_{base}$
  - 水平黑边偏移：$O_x = \frac{W - V_w}{2}$
  - 缩放系数：$S = \frac{H}{H_0} = \frac{V_w}{W_0}$

* **情况 B：窄屏/平板 ($R_{screen} < R_{base}$)**
  - 水平方向撑满：$V_w = W, \quad O_x = 0$
  - 垂直有效视口：$V_h = \frac{W}{R_{base}}$
  - 垂直黑边偏移：$O_y = \frac{H - V_h}{2}$
  - 缩放系数：$S = \frac{W}{W_0} = \frac{V_h}{H_0}$

#### 步骤 2：基于锚点（Anchor）的坐标映射计算
每个 UI 坐标 $(x_0, y_0)$ 在定义时赋予一个锚点属性：

| 锚点类型 (Anchor) | 适用典型控件 | X 轴坐标推导公式 $X_{new}$ | Y 轴坐标推导公式 $Y_{new}$ |
| :--- | :--- | :--- | :--- |
| **Center** (视口居中) | 选卡、宝具卡、弹窗确认、苹果 | $O_x + \frac{V_w}{2} + (x_0 - \frac{W_0}{2}) \times S$ | $O_y + \frac{V_h}{2} + (y_0 - \frac{H_0}{2}) \times S$ |
| **BottomLeft** (左下吸附) | 从者 1~9 技能、令咒状态 | $O_x + x_0 \times S$ | $H - (H_0 - y_0) \times S$ |
| **BottomRight** (右下吸附) | Attack 按钮、结算 Next 按钮 | $W - (W_0 - x_0) \times S$ | $H - (H_0 - y_0) \times S$ |
| **TopRight** (右上吸附) | 御主技能展开按钮、战斗 Menu | $W - (W_0 - x_0) \times S$ | $O_y + y_0 \times S$ |
| **TopLeft** (左上吸附) | 敌方目标 1~3 序号、撤退确认 | $O_x + x_0 \times S$ | $O_y + y_0 \times S$ |

找图检测区域 `[x1, y1, x2, y2]` 的左右上角点同样应用此公式推导，确保检测窗口与控件完全对齐。

### 3.1 模块 A：动态资源池与免打包加载架构 (Runner 底层改造)
1. **突破 `.atc` 附件包限制**：
   - 按键精灵原生支持绝对路径找图。Runner 中封装找图探测函数：
     ```vb
     Function ResolveImagePath(imgFileName)
         Dim sdPath = "/sdcard/FGO_Q/images/" & imgFileName
         If File.Exist(sdPath) Then
             ResolveImagePath = sdPath
         Else
             ResolveImagePath = "Attachment:" & imgFileName
         End If
     End Function
     ```
   - 既保证了对原有 `.atc` 附件包的 100% 向下兼容，又完全解锁了免打包热推新图的能力。
2. **坐标体系独立文件化**：
   - 将原硬编码在 Runner 中的近百个常量数组抽取为独立的 `battle_v5_coords.q`（以及模拟器端 `battle_v5_coords.mq`）。
   - Runner 启动时动态读取，彻底解耦！

### 3.2 模块 B：视觉特征资产中心与 Web 标定工作台 (Visual Asset Center & Calibration Studio)

#### 3.2.1 仓库既有图片资产全量透出与检索
1. **仓库资产基线挂载**：
   - 服务端启动时，自动扫描并直通当前仓库内的既有图片目录 `images/attached images/`（涵盖当前已有的 96+ 项特征模板，如 `ATTACK_BTN.png`、`APPLE_DISPLAY.png`、`friendAobao1.png` 等）。
   - 实现**多级图片寻址加载机制**：
     ```python
     def resolve_image_path(self, fname):
         # 1. 优先检查本地高优缓存/编辑目录
         local_path = os.path.join(self.images_dir, fname)
         if os.path.isfile(local_path):
             return local_path
         # 2. 检索仓库基准图库
         repo_path = os.path.join(self.repo_images_dir, fname)
         if os.path.isfile(repo_path):
             return repo_path
         return None
     ```
2. **Web 资产图谱与目标向导**：
   - 在前端标定工作台的左侧面板与资产抽屉中，直观渲染所有目标的**高清缩略图、图像分辨率规格、绑定锚点类型**。
   - 状态指示清晰：
     - 🟢 **已具备（仓库库内）**：直观展示既有缩略图，用户点击即可在主画布中比对当前模拟器位置；
     - 🟡 **未标定/待截取**：提示无对应模板，引导拉框裁切；
     - 🔵 **已热更**：标明属于本次会话中新标定且已推送到模拟器的图片。
   - 分类筛选：支持快速过滤 `battle`（战斗与出牌）、`skill`（技能与选人）、`reward`（结算与掉落）、`friend`（助战从者与礼装）、`enhance`（强化育成）等类别。

#### 3.2.2 视觉特征双套坐标范围规范 (Dual-Coordinate Scope Model)
每个视觉特征资产（Target）在架构体系中均定义**两套职责明确的坐标矩形** `[x1, y1, x2, y2]`：

1. **运行时匹配范围 (`search_area` / `match_area`)**：
   - **职能定义**：执行引擎（Runner）在脚本运行期间调用 `FindPic` 的屏幕搜索扫描窗口。
   - **坐标特性**：**适度外扩，宽广容差**。为了抵御游戏动效抖动、渲染延迟或微小位移，搜索区域通常比目标本体外扩 20%~50%（如 Attack 按钮本体约 150×50，但搜索窗口设为 `[1200, 700, 1350, 750]`）。
   - **自适应行为**：在多屏幕长宽比适配时，结合视口黑边偏移量与锚点公式，动态实时推导实机搜索坐标。
   - **初始状态**：仓库既有预设均已具备完整的基准搜索值（继承自 V4 原生体系）。

2. **截取图片的坐标范围 (`crop_area`)**：
   - **职能定义**：模板图片本身在基准分辨率（$1440\times 810$）上的**精确像素裁切边界**。
   - **坐标特性**：**像素级精准贴合**，严格决定裁切出的特征 PNG 文件的实际宽高尺寸与图像内容。
   - **初始状态与未来价值**：
     - **当前初始状态**：仓库现存图片来源于历史工程提取，原始裁切坐标目前均无留存记录，因此系统将其统一初始化为空值 `null`。
     - **未来演进收益**：一旦用户在 Web 标定工作台上拉框标定并点击保存，系统将精确矩形持久化写入 `crop_area`。后续游戏大版本更新 UI 微调、推出同构换皮活动界面、或需要重新截取高保真图片时，点击该目标即可**一键自动对齐/复位到预设裁切选区**，无需人工再次凭借肉眼重新找坐标拉框，实现秒级高精度复刻重截！

| 维度对比 | 运行时匹配范围 (`search_area`) | 截取图片的坐标范围 (`crop_area`) |
| :--- | :--- | :--- |
| **应用阶段** | 模拟器内脚本常驻运行（找图识别） | Web 标定工作台制图阶段（截取制作模板） |
| **矩形范畴** | 覆盖目标及周围微移容差的宽松搜索窗口 | 贴合模板图像素边缘的紧致裁切矩形 |
| **当前状态** | 完整具备基准预设值（继承自 V4 核心配置） | **当前统一为空 (`null`)**，预留未来标定沉淀 |
| **多分辨率推导** | 运行时随视口黑边和锚点自适应伸缩 | 绑定基准分辨率 ($1440\times 810$)，用于复位选框 |
| **核心收益** | 降低找图耗时、杜绝全屏误判 | **重截图时一键自动对齐选区，免除重复拉框** |

#### 3.2.3 裁切保存的“双通道同步落盘流水线” (Dual-Destination Pipeline)
当用户在 Canvas 完成框选、对齐锚点并点击「💾 裁切并保存」时，后端触发原子级双通道执行：

1. **通道 A：代码仓库资产原位替换 (Repo In-Place Overwrite & Git Versioning)**
   - 目标路径定位至仓库源码目录：`images/attached images/{fname}`；
   - **防误触安全快照**：若该文件在仓库中已存在，系统自动先复制一份至 `editor_v5/backup_images/{target}_{timestamp}.png`，确保历史资产随时可一键找回；
   - **原位覆写**：将裁切出的高质量 PNG 写入仓库目录，并同步刷新 `editor_v5/images/` 资产缓存；
   - **价值**：代码仓库始终与实际标定保持 100% 真实同步，开发者 `git diff` / `git status` 可以清晰感知特征图的改动，提交即可完成团队共享。
2. **通道 B：模拟器动态图片池毫秒级热推 (Instant ADB Push)**
   - 后端获取当前连接的模拟器设备，通过 ADB 命令行静默执行：
     ```bash
     adb -s <device> push "<saved_png_path>" "/sdcard/FGO_Q/images/<fname>"
     ```
   - 耗时通常 `< 200ms`，无需重启按键精灵脚本，模拟器内的 `ResolveImagePath` 在下一次循环检测中直接加载新图；
   - 彻底消灭打开 PC 助手导入附件包重新打包的繁琐流程。

#### 3.2.4 双套范围同屏呈现与双向交互编辑体系 (Dual-Scope Simultaneous Canvas & Inspector)
- **同屏视觉分层呈现 (Simultaneous Canvas Rendering)**：
  - 🔍 **运行时匹配范围 (Search Area)**：渲染为**科技蓝**线框，未激活状态呈现优雅虚线（`[6, 4]`），激活状态呈现 2.5px 亮蓝边框与蓝色光晕，顶部显示动态标牌 `🔍 匹配范围: W×H`；
  - ✂️ **截图裁切选区 (Crop Area)**：渲染为**荧光绿**线框，2px/3px 实线高亮与绿色光晕，顶部显示动态标牌 `✂️ 截图选区: W×H`（具备智能避让机制，两框上边缘重叠时自动避让到下边缘，绝不遮挡）；
  - 🎯 **点击锚点 (Tap Point)**：渲染为**醒目红**十字准星与中心靶点，标注精确 `Tap (X, Y)` 坐标。
- **顶部工具栏图层控制规范 (Toolbar Layer Controls)**：
  - **独立显示/隐藏勾选 (Visibility Checkbox)**：顶部提供「✂️ 截图选区」与「🔍 匹配范围」复选框，默认均处于勾选显示状态。用户可根据需要随时取消勾选以隐藏对应层，画布即时清爽渲染；
  - **唯一可编辑状态控制 (Mutually Exclusive Editable Radio)**：分别提供「可编辑」切换药丸按钮（内部采用 Radio 单选互斥机制，**同时仅能有一种处于可编辑状态**）。选中的图层在画布上高亮发光并显示 8 控制手柄，支持拖拽平移与缩放；未选中的图层保持静态线框仅供视觉参考，绝不产生误触；
  - **智能联动保护**：当勾选某一层为「可编辑」时，系统自动确保其「显示」复选框勾选可见；若隐藏当前正处于编辑状态的图层，系统将自动将编辑权移交至另一可见图层。
- **全自由度双向交互编辑能力 (Interactive Manipulation)**：
  - **8 向手柄精确拉伸**：激活选框具有 8 个高对比控制手柄（`nw, n, ne, e, se, s, sw, w`），鼠标悬停自动呈现相应调整光标（`nwse-resize`, `nesw-resize` 等），拖拽即可像素级修改该范围；
  - **整体拖拽平移**：鼠标在框内按下可直接全选平移，自动受限于画布边界；
  - **点击智能切换激活**：点击任一范围（蓝框或绿框）自动切换编辑焦点与顶部工具栏模式；
  - **空白区域重新框选**：在空白处直接按下鼠标拖拽，立即为当前激活模式绘制全新矩形；
  - **双卡片数值精准微调**：右侧检查器分为绿色的「截图裁切范围 (Crop Area)」卡片与蓝色的「运行时匹配范围 (Search Area)」卡片，支持直接输入数值 `[X1, Y1, X2, Y2]`，输入框聚焦时自动高亮对应卡片并联动画布，按像素精确调优；
  - **✨ 智能识别截图区域 (Auto-Detect Crop Area)**：历史图片资产若尚未预设截图选区（`crop_area: null`），提供一键「✨ 智能识别截图区域」按钮，基于库内成熟特征图结合匹配搜索窗口，在当前画面中自动毫秒级对齐并生成精确像素选区，免去肉眼手动框选；
  - **辅助工具纽带**：提供「由截图框外扩 (+30px)」等辅助功能，实现两套坐标之间的高效同步与自动推导。



#### 3.2.5 OpenCV 模板匹配测试验证 (Verify Match)
- 保存前可一键触发「🔍 测试匹配」；
- 后端调用 `cv2.matchTemplate(..., cv2.TM_CCOEFF_NORMED)` 计算全屏或局部搜索框内的最大相关系数；
- 界面即时显示匹配置信度（如 `98.7% MATCH`）并用绿色荧光框标出命中区域，确保 100% 可用后再确认替换。

#### 3.2.6 纯点击锚点管理体系 (Pure Tap Anchors System)
- **业务背景**：FGO 脚本中有大量不需要图像比对的固定交互（如 9 个从者技能、3 个选人施法位置、6 个换人顺序位置、4 个御主技能、6 个敌方选怪目标、8 个出牌指令卡等）。历史工程将这些坐标硬编码在脚本数组中，导致在标定工具中“找不着”且无法直观维护。
- **资产化纳入与分类隔离**：
  - 将 40 个原生战斗固定交互坐标统一注册进 `profiles/default_1440x810.json`，标记为 `category: "tap"`；
  - 左侧面板新增专属「🎯 点击锚点」分类过滤标签，展示独立靶心图标与状态指示，与传统视觉图源清晰隔离；
- **纯点击专属交互优化**：
  - **画布左键即点即设**：选中纯点击锚点时，鼠标在模拟器当前画面的任意位置左键点击即可直接重定位该锚点，并支持直接按住拖拽微调，无需繁琐拉框；
  - **局部放大准星视口**：右侧小图预览自动居中截取点击坐标周围 $140\times 140$ 像素的画面并叠加大十字准星，一目了然看清点击中心点是否偏离目标按钮中心；
  - **免图像裁切纯坐标保存**：工具栏保存按钮自动变更为「💾 保存点击锚点」，无需生成 PNG 文件，后端直接原子持久化更新 JSON 配置文件中的 `tap_coord` 与锚点属性。

### 3.3 模块 C：多环境预设（Profiles）与资产版本管理
- 支持多套分辨率 Profile 保存（例如 `1440x810_standard.json`、`1280x720_mumu.json`、`2400x1080_full.json`）。
- 每次图片覆盖更新时自动在 `editor_v5/backup_images/` 生成时间戳备份，支持活动结束后一键回退历史 UI。
