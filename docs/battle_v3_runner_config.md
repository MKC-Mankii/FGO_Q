# Runner 与配置文件说明（v3 版本）

本文档详细说明 FGO Q 脚本体系的 **v3 版本架构**，涵盖 `battle_v3_runner.q`、`battle_v3_config.q` 以及全新的可视化配置编辑器（Web Editor）。

---

## 1. v3 核心演进与改进

相比 v2 旧版本，v3 版本在配置管理、大组规范和可视化编辑方面进行了全面重构：

1. **配置命名规范化与纯净化**：
   - 废弃了 v2 中混杂有 `TEST_` 前缀的变量格式（如 `TEST_DSL_G2_1` 等）。
   - 统一采用规范的 `DSL_Gx_y` 和 `FRIEND_Gx_y`，各组结构完全对称一致。
2. **大组体系语义化重构**：
   - **大组 0（`test`）**：独立测试大组。每套方案均支持独立配置助战，不再依赖全局覆盖。
   - **大组 1（`campaign`）**：活动关卡配置。
   - **大组 2（`caber`）**：术呆常用战斗配置。
   - **大组 3（`grand`）**：戴冠战关卡配置（原 `order_saber` 正式更名为 `grand`）。
   - **大组 4（`ordeal`）**：白纸化地球 Ordeal Call 关卡配置。
3. **原生可视化网页编辑器**：
   - 位于 `editor/battle_config_editor.html`，由轻量级本地服务 `editor/server.py` 驱动。
   - **全鼠标点击录入**：从者技能（附带目标选择浮窗）、御主换人（前排 ⇄ 后排弹窗）、敌方目标锁定、三张出牌槽位（色卡优先/宝具选择）。
   - **直读直存本地文件**：打开页面自动加载 `Q/battle_v3_config.q`，支持界面点击保存或 `Ctrl + S` 快捷键直接写入磁盘，彻底告别繁琐的手工复制粘贴或文件下载/导入。

---

## 2. 核心文件体系与链路

### 文件分工

- `Q/battle_v3_runner.q`：**战斗逻辑执行主脚本**
  - 负责图像识别、点击逻辑、选卡发牌、循环轮次控制。
  - 启动时自动在手机存储目录中检索 `.mq` 编译产物，解析出 `CFG_*` 参数。
  - 仅在顶部手动指定当前生效的大组编号：`Dim CFG_ACTION_GROUP_INDEX = 3`。
- `Q/battle_v3_config.q`：**纯配置源文件**
  - 仅保存各个大组、各个关卡方案的纯数据（`Dim PRESET = ...`、`Dim FRIEND_Gx_y = ...`、`Dim DSL_Gx_y = ...`）。
  - 不包含任何流程与动作执行逻辑，可通过编辑器随时修改。
- `editor/battle_config_editor.html`：**可视化配置编辑器**
  - 前端界面，以图形化卡片方式组织大组（0~4）、方案（1~N）与回合（Wave 1~3+）。
- `editor/server.py`：**本地服务与 API 桥梁**
  - 提供 `GET /api/config` 和 `POST /api/save` 接口，使网页可直接读写 `Q/battle_v3_config.q`。

### 运行链路示意

```
[ 用户在浏览器操作编辑器 (http://127.0.0.1:8099) ]
         │
         ▼ (Ctrl + S 自动保存)
[ 磁盘文件: Q/battle_v3_config.q ]
         │
         ▼ (按键精灵 PC 端编译同步)
[ 手机存储: /sdcard/MobileAnJian/Script/battle_v3_config(...).mq ]
         │
         ▼ (运行时自动扫描读取)
[ 手机执行: Q/battle_v3_runner.q 执行战斗 ]
```

## 3. v3 配置字段规范说明

### 3.1 全局字段

- `PRESET`：配置预设标记，主要用于日志打印（例如 `"campaign"`）。
- `ACTIVITY_REWARD`：活动结算/奖励确认流程开关（`1` 为开启，`0` 为关闭）。

### 3.2 大组索引与选择

- `CFG_ACTION_GROUP_INDEX`（**仅在 `battle_v3_runner.q` 中手动设置**）：
  - `0` = `test`（测试大组）
  - `1` = `campaign`（活动关卡）
  - `2` = `caber`（术呆常用）
  - `3` = `grand`（戴冠战关卡）
  - `4` = `ordeal`（白纸化地球 Ordeal Call）
- `ACTION_ROUND_INDEX_Gx`（在 `battle_v3_config.q` 中配置）：
  - 声明大组 `x` 默认生效第几套方案（例如 `Dim ACTION_ROUND_INDEX_G1 = 2` 表示大组 1 默认选用方案 2）。

### 3.3 助战字段

- `FRIEND_Gx_y`：第 `x` 大组第 `y` 方案专用的助战关键字（例如 `FRIEND_G1_1 = "mary"`）。
- `FRIEND_Gx`：第 `x` 大组的默认/兜底助战关键字（例如 `FRIEND_G0 = "aobao"`）。
- `FRIEND`：全局助战兜底关键字（可选）。
- **优先级**：`FRIEND_Gx_y` > `FRIEND_Gx` > `FRIEND`。

#### 支持的助战关键字列表（不区分大小写）
`aobao`, `aobaoshan`, `cdai`, `daoman`, `cba`, `rba`, `rbashan`, `shahu`, `shahushan`, `princess`, `princess120`, `taigong`, `sparrow`, `mary`, `keli`, `bdai`

### 3.4 战斗动作 DSL 字段

- 格式：`Dim DSL_Gx_y = "..."`
- 对应第 `x` 大组的第 `y` 套战斗方案。
- 各回合之间使用分号 `;` 分隔。若包含 3 个 Wave，则配置为形如：`Wave1动作;Wave2动作;Wave3动作`。

## 4. 可视化编辑器（Web Editor）使用指南

### 4.1 启动编辑器

在终端或后台启动本地服务端：
```bash
python editor/server.py
```
在浏览器中打开：
```
http://127.0.0.1:8099/battle_config_editor.html
```

### 4.2 界面功能结构

1. **顶栏状态与控制**：
   - 显示连接状态与当前同步的文件路径（自动识别为 `Q/battle_v3_config.q`）。
   - 提供「从本地重新读取」与「立即保存到本地文件 (Ctrl+S)」按钮。
2. **大组切换栏**：
   - 快速在 `0: test`、`1: campaign`、`2: caber`、`3: grand`、`4: ordeal` 之间切换。
3. **方案选择与管理**：
   - 切换当前大组下的方案 1、2、3...；
   - 支持独立设置当前方案的「专属助战从者」。
4. **回合（Wave）流动作编辑区**：
   - **回合切换**：在第 1 回合、第 2 回合、第 3 回合之间切换；支持新增回合。
   - **时间线动作胶囊**：直观展示已添加的锁定目标、从者技能、御主技能、换人动作，点击 `×` 即可单个移除。
   - **技能动作选择板**：
     - **从者技能 1~9**：点击对应按钮，弹出轻量气泡，可选择目标（无目标 / 从者1 / 从者2 / 从者3）。
     - **御主技能 1~3**：御主 1~2 技能支持目标选择，御主 3 技能提供图形化换人弹窗（选择前排 1~3 与后排 4~6 交换）。
     - **锁定敌方目标**：点击「敌方 1 (左)」、「敌方 2 (中)」、「敌方 3 (右)」直接插入锁定动作。
   - **出牌槽位配置**：
     - 三个槽位下拉选择：支持宝具卡（从者 1/2/3 宝具卡 `6` / `7` / `8`）、自动选卡优先级（红卡优先 `B` / 蓝卡优先 `A` / 绿卡优先 `Q`）以及指定卡位（`1`~`5`）。
5. **代码实时预览与快捷键**：
   - 下方代码区实时展示最新生成的完整 Q 代码。
   - 任意时刻按键盘快捷键 `Ctrl + S`（Mac 为 `Command + S`），直接保存并写入 `Q/battle_v3_config.q`。

## 5. DSL 动作指令语法参考

DSL 用于指导单回合内的所有操作序列：

| 语法符号 | 作用 | 示例 | 含义 |
| :--- | :--- | :--- | :--- |
| `;` | 分隔不同回合（Wave） | `Wave1;Wave2;Wave3` | 回合 1 结束后等待下回合执行 Wave 2 |
| `\|` | 分隔同回合内的动作单元 | `s10 \| m22 \| a7, 4, 5` | 先放从者技能，再放御主技能，最后出牌 |
| `,` | 分隔同类型参数或动作 | `s20, 30, 40` / `a7, 8, 5` | 连续释放 2、3、4 技能；依次打出 7号宝具、8号宝具、5号卡 |

### 动作代码格式

- **从者技能 `sXY`**：
  - `X` = 技能编号 1~9（1号位从者 1~3 技能；2号位从者 4~6 技能；3号位从者 7~9 技能）。
  - `Y` = 技能作用目标 0~3（`0`=无目标/自身；`1`~`3`=目标从者位置）。
  - 示例：`s52`（2号位从者的第2个技能，施加给2号位从者）。
- **御主技能 `mXY`**：
  - `X` = 御主技能 1~3。
  - `Y` = 作用目标 0~3（`0`=无目标）。
  - 示例：`m22`（御主2技能，加给2号位从者）。
- **御主换人技能 `mX00AB`**：
  - `X` = 御主换人技能编号（通常为 `3`）。
  - `A` = 被换下的前排位置（1~3）。
  - `B` = 换上的后排位置（4~6）。
  - 示例：`m30024`（使用御主 3 技能，将 2 号位前排与 4 号位后排交换）。
- **锁定目标 `tX`**：
  - `t1`=左侧敌人，`t2`=中间敌人，`t3`=右侧敌人。
- **攻击出牌 `aX,Y,Z`**：
  - `X,Y,Z` 分别代表选出的第 1、2、3 张指令卡。
  - `6` / `7` / `8`：分别代表 1、2、3 号位从者的宝具卡。
  - `B` / `A` / `Q`：分别代表优先选择 Buster (红)、Arts (蓝)、Quick (绿) 色卡。
  - `1`~`5`：指定固定卡位。
  - 示例：`a7, B, B`（先打出 2 号位从者宝具，后续两张优先选择红卡）。

## 6. 配置文件识别与排错指南

### 6.1 文件扫描规则

`battle_v3_runner.q` 启动时通过按键精灵的 `zm.DirScan` 扫描以下目录中的 `.mq` 文件：
- `/sdcard/MobileAnJian/Script/`
- `/storage/emulated/0/MobileAnJian/Script/`

**识别优先级**：
1. 文件名包含 `battle_v3_config` 或 `battle_config_v3` 的 `.mq` 文件（**v3 优先**）。
2. 若未找到 v3，则兜底检查 `battle_v2_config`、`battle_config_v2` 或 `battle_config` 的 `.mq` 文件。

### 6.2 常见错误与解决方法

| 日志输出 | 常见原因 | 解决办法 |
| :--- | :--- | :--- |
| `CONFIG PATH NOT FOUND` | 手机上未找到编译同步后的 `.mq` 文件 | 在按键精灵电脑端打开 `battle_v3_config.q` 并点击「保存并同步」到手机上 |
| `FRIEND CONFIG INVALID OR EMPTY, STOP` | 当前大组方案的助战字段为空或名称不匹配 | 在网页编辑器中检查对应方案的助战配置，确保填写为受支持的名字缩写 |
| `CONFIG DSL EMPTY, STOP` | 当前大组方案的 DSL 为空 | 在网页编辑器中为该方案添加技能与出牌动作，并按 Ctrl+S 保存 |
| 无法在网页端保存 (Save Failed) | `server.py` 服务未开启或端口冲突 | 在终端运行 `python editor/server.py` 确保服务在 8099 端口正常运行 |
