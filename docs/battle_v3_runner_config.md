# Runner 与配置文件说明（v3 版本）

本文档说明 FGO Q 脚本体系 **v3 版本架构**，涵盖 `battle_v3_runner.q`（战斗执行引擎）、`battle_v3_config.q`（战斗配置数据）以及配套的可视化配置编辑器（Web Editor）。

---

## 1. v3 核心演进

相比 v2 版本，v3 版本进行了以下重构：

1. **配置命名规范统一**：废弃 v2 混杂的 `TEST_` 前缀，全面统一为 `DSL_Gx_y` 与 `FRIEND_Gx_y`，各组配置结构保持严格对称一致。
2. **大组体系语义化**：按战斗业务场景划分为 5 个大组（测试、活动、术呆常用、戴冠战、白纸化地球），每套方案均支持独立配置助战，不再依赖全局覆盖。
3. **引入可视化配置编辑器**：提供轻量本地 Web 编辑器，支持多回合时序看板、可视化技能与出牌录入、拖拽重排、自动备份与一键读写。

---

## 2. 核心文件体系与链路

### 2.1 文件分工

- `Q/battle_v3_runner.q`：**战斗执行主脚本**
  - 负责图像识别、点击交互、出牌判定、轮次循环与异常处理。
  - 启动时自动扫描并解析 `battle_v3_config` 编译产物中的配置变量。
  - 在脚本顶部手动指定当前生效的大组编号：`Dim CFG_ACTION_GROUP_INDEX = 3`。
- `Q/battle_v3_config.q`：**战斗配置源文件**
  - 仅保存数据声明（`DSL_Gx_y`、`FRIEND_Gx_y`、`ACTION_ROUND_INDEX_Gx` 等），不含任何流程与执行逻辑。
- `Q/.backup/`：**自动快照备份目录**
  - 编辑器每次保存时，自动将保存前的配置文件备份为 `battle_v3_config.q.YYYYMMDD_HHMMSS.bak.q`（自动保留最近 10 份快照）。
- `editor/`：**Web 可视化编辑器**
  - `server.py`：轻量本地服务，提供配置读写 API、自动轮转备份与静态页面托管（默认端口 `8099`）。
  - `index.html` / `battle_config_editor.html`：编辑器页面。
  - `css/` 与 `js/`：模块化前端实现，负责 DSL 解析、视图渲染、时序看板与交互控制。

### 2.2 运行链路

```
[ 浏览器操作 Web 编辑器 (http://127.0.0.1:8099) ]
         │
         ▼ (Ctrl + S 保存)
[ 自动快照备份: Q/.backup/battle_v3_config.q.(时间戳).bak.q ]
         │
         ▼ (写入本地磁盘)
[ 配置文件: Q/battle_v3_config.q ]
         │
         ▼ (按键精灵 PC 端保存并同步编译)
[ 手机存储: /sdcard/MobileAnJian/Script/battle_v3_config(...).mq ]
         │
         ▼ (启动时自动扫描加载)
[ 战斗执行: Q/battle_v3_runner.q ]
```

## 3. 配置字段规范

### 3.1 大组与方案选择

- **大组编号 `CFG_ACTION_GROUP_INDEX`**（在 `battle_v3_runner.q` 顶部指定）：
  - `0` = `test`（测试大组）
  - `1` = `campaign`（活动关卡）
  - `2` = `caber`（术呆常用）
  - `3` = `grand`（戴冠战关卡）
  - `4` = `ordeal`（白纸化地球 Ordeal Call）
- **默认方案索引 `ACTION_ROUND_INDEX_Gx`**（在 `battle_v3_config.q` 中配置）：
  - 指定大组 `x` 默认生效的方案序号。例如 `Dim ACTION_ROUND_INDEX_G1 = 2` 表示大组 1 默认选用方案 2。

### 3.2 战斗动作 DSL 字段

- **字段格式**：`Dim DSL_Gx_y = "..."`
  - 对应大组 `x` 的第 `y` 套战斗方案。
  - 回合间使用分号 `;` 分隔，格式为：`Wave1动作;Wave2动作;Wave3动作`。
  - （大组 0 额外兼容旧字段 `TEST_DSL` / `TEST_DSL_y`）。

### 3.3 助战字段

- `FRIEND_Gx_y`：大组 `x` 方案 `y` 专属助战关键字（例如 `FRIEND_G1_1 = "mary"`）。
- `FRIEND_Gx`：大组 `x` 默认助战关键字（例如 `FRIEND_G0 = "aobao"`）。
- `FRIEND`：全局助战兜底关键字（可选）。
- **生效优先级**：`FRIEND_Gx_y` > `FRIEND_Gx` > `FRIEND`。

#### 支持的助战关键字（不区分大小写）
| 类别 | 助战关键字 |
| :--- | :--- |
| 拐位从者 | `aobao`（奥伯龙）、`aobaoshan`（灵三奥伯龙）、`cdai`（C呆）、`cba`（术斯卡蒂）、`rba`（尺斯卡蒂）、`rbashan`（灵三尺斯卡蒂）、`daoman`（道满）、`shahu`（杀狐）、`shahushan`（灵三杀狐） |
| 打手/通用 | `princess`（爱尔奎特）、`princess120`（百二十级爱尔奎特）、`taigong`（太公望）、`sparrow`（红阎魔）、`mary`（骑玛丽）、`keli`（克洛伊） |

> **注意**：助战关键字必须与 `battle_v3_runner.q` 内预置的特征图片（`Attachment:friend*.png`）匹配；如配置未被支持的关键字，脚本启动时将停止并提示 `FRIEND CONFIG INVALID OR EMPTY`。

### 3.4 活动领奖开关

- `ACTIVITY_REWARD_Gx_y`：大组 `x` 方案 `y` 专属活动点数/结算领奖开关（`1` 开启，`0` 关闭，默认 `0`）。Runner 优先读取当前生效方案的独立配置。
- `ACTIVITY_REWARD_Gx`：大组 `x` 的活动结算兜底开关（可选）。
- `ACTIVITY_REWARD`：全局活动领奖兜底开关（默认 `0`）。
- **生效优先级**：`ACTIVITY_REWARD_Gx_y` > `ACTIVITY_REWARD_Gx` > `ACTIVITY_REWARD`。

## 4. DSL 动作指令语法参考

DSL 用于定义单回合内执行的所有操作序列：

### 4.1 语法结构符

| 符号 | 作用 | 示例 | 说明 |
| :---: | :--- | :--- | :--- |
| `;` | 分隔回合（Wave） | `Wave1;Wave2;Wave3` | 回合执行完毕后，等待下一回合载入 |
| `\|` | 分隔动作单元 | `s10 \| m22 \| a6, B, B` | 依次执行从者技能、御主技能、收尾出牌 |
| `,` | 分隔同类动作或参数 | `s10, 20, 30` / `a7, 4, 5` | 连续释放多个技能；按顺序指定 3 张出牌 |

### 4.2 动作代码说明

#### 1. 从者技能 `sXY`
- `X`：技能编号 1~9（1~3 号为 1 号位从者技能，4~6 号为 2 号位技能，7~9 号为 3 号位技能）。
- `Y`：目标位置 0~3（`0` = 无目标/自身，`1`~`3` = 目标从者位置）。
- **示例**：`s52`（2 号位从者的第 2 个技能，作用于 2 号位从者自身）；`s10, 20, 30`（连续释放 1 号位的三个无目标技能）。

#### 2. 御主技能 `mXY` 与换人 `mX00AB`
- **普通技能**：`mXY`
  - `X`：御主技能号 1~3。
  - `Y`：目标位置 0~3（`0` = 无目标，`1`~`3` = 目标从者）。
  - **示例**：`m22`（御主 2 技能，目标为 2 号位从者）。
- **换人技能**：`mX00AB`
  - `X`：换人技能号（通常为 `3`）。
  - `A`：换下的前排从者（1~3）。
  - `B`：换上的后排从者（4~6）。
  - **示例**：`m30034`（使用御主 3 技能，将前排 3 号位与后排 4 号位交换）。

#### 3. 敌方目标锁定 `tX`
- `t1` ~ `t6`：选中敌方目标（1~3 为上排左/中/右，4~6 为下排左/中/右）。
- 坐标预置在 `battle_v3_runner.q` 的 `BATTLE_TARGET_COORDS`：
  - 上排：`t1(159, 33)`, `t2(424, 33)`, `t3(689, 33)`
  - 下排：`t4(130, 150)`, `t5(355, 150)`, `t6(580, 150)`

#### 4. 攻击出牌 `aX, Y, Z`
- `X, Y, Z` 严格按序对应出牌的第 1、第 2、第 3 张卡。
- **卡牌代号**：
  - `6` / `7` / `8`：分别代表 1、2、3 号位从者的**宝具卡**（每回合各至多选 1 次）。
  - `1` / `2` / `3` / `4` / `5`：代表屏幕从左至右的 5 张**手牌位置卡**（对应普卡 1~5）。
  - `B` / `A` / `Q`：代表优先选择红卡、蓝卡、绿卡的**优先色卡**（支持同色卡重复选入，如 `B, B, B`）。
- **示例**：
  - `a6, B, B`：1 号从者宝具 + 后续选 2 张红卡。
  - `a7, 4, 5`：新建方案/回合的标准默认出牌（2 号从者宝具 + 第 4 张普卡 + 第 5 张普卡）。

## 5. 可视化编辑器（独立桌面应用）使用指南

### 5.1 启动与关闭

- **一键桌面启动（推荐）**：
  - 双击桌面或项目根目录下的 **`FGO_Config_Editor`** 快捷方式（Saber 金卡图标），直接以**独立桌面应用程序窗口**启动（基于 `pywebview` / WebView2 引擎），完全脱离浏览器，无任何地址栏、标签页或黑框终端打扰。
  - 亦可使用 `editor/start_editor.bat` 或 `editor/start_editor.vbs` 备用启动。
- **一键退出关闭**：
  - **窗口原生关闭（推荐）**：直接点击桌面窗口右上角的 **`×`** 关闭窗口，主进程与后台网络服务将自动彻底退出，端口即刻释放，0 后台孤儿进程残留。
  - **脚本备用退出**：双击运行 `editor/stop_editor.bat` 亦可快速终止后台残留服务进程。
- **手动命令行启动（备用）**：
  ```bash
  python editor/launcher.py
  ```
  如仅需纯 Web 端口调试模式：
  ```bash
  python editor/server.py
  ```
  访问地址：`http://127.0.0.1:8099`

### 5.2 界面功能结构

1. **顶部主栏（Masthead）**：
   - **左上角标题与图标**：显示 Saber 金卡应用图标与 `Battle Config Editor` 标题。
   - **右上角系统微型工具栏**：提供系统辅助功能——恢复推荐窗口尺寸（`📐 1600×1020`，适配高分屏免滚动展开）、刷新页面代码（`🔄`，快捷键 `F5` / `Ctrl+R`）、在系统浏览器中打开（`🌐`）。
   - **核心配置操作区**：显示自动读取状态，提供「📂 重新读取」、「📋 复制配置」与「💾 保存配置 (Ctrl+S)」。
2. **战场选项卡栏（Battlefield Tabs Bar）**：
   - **区域标题**：左侧带有蓝色色标与战域地图图标的「`🗺️ 战场`」标志性模块标题及分割线。
   - **精简 Tab 标签**：去除了标签内冗余的前缀，仅显示战场景名或编号。
   - **标准数量徽标（Badge）**：方案数量采用胶囊样式纯数字徽标展示（如 `1`、`3`）。
   - **悬浮提示（Tooltip）**：战场详细说明与方案总数均收纳在鼠标移入选项卡的浮动提示中，极致节省纵向空间。
3. **方案侧边栏（Scheme List）**：
   - 宽度紧凑化（165px），以金星图标（`⭐`）直观标记默认方案，以礼盒图标（`🎁`）直观标记开启点数领奖的方案。
   - 拖拽侧边栏手柄 `⋮⋮` 可快速重排方案顺序。
   - 点击「+ 加方案」追加新方案；底部提供「🔄 重置配置」。
4. **方案属性与 DSL 工具**：
   - **默认方案星标开关**：位于方案标题最左侧，以撑满标题栏高度的独立方框呈现。当前方案为默认方案时显示金色实心星（`⭐`），非默认方案时显示空心星（`☆`），点击可一键切换为该战场的默认执行方案。
   - **方案重命名**：支持点击方案名称直接重命名（如 `活动 90++ 3T`），点击打勾或回车立即保存。
   - **助战选择**：下拉框快速选取拐位/打手关键字（如 `cba`、`aobao`），支持输入框模糊搜索与自定义关键字输入。
   - **点数奖励开关**：位于助战右侧，支持每个方案独立开关活动点数领取（勾选为开启），结算时自动执行领奖点击确认。
   - **复制 / 导入 DSL**：一键导出当前方案 DSL 文本；导入时支持智能识别剪贴板格式，支持覆盖当前方案或新建为方案。
5. **多回合时序看板（Action Timeline Board）**：
   - 各回合（Wave）按时序卡片化展示技能、换人、目标与出牌操作。
   - 拖动回合左侧手柄 `⋮⋮` 可上下调换回合执行顺序。
   - 点击卡片可就地修改参数或点击 `×` 删除；出牌卡片按 3 槽位显示对应颜色与标签。
   - 支持「+ 添加下一回合」、「清空动作」与「删除回合」。
6. **录入控制台（Action Palette）**：
   - **敌方锁定**：1~6 号目标直选锁定。
   - **从者技能**：按从者 1~3 分组列出技能 1~9，支持直接释放或按键直选目标从者。
   - **御主技能与换人**：提供御主技能 1~3；换人功能以 3 号技能触发，直选前排与后排交换人选。
   - **收尾出牌（3-Slot 模型）**：提供宝具卡（6~8）、优先色卡（B/A/Q）和手牌卡（1~5），按点击顺序占用 1~3 槽位，支持独立取消单槽或一键清空。

## 6. 排错与运维指南

### 6.1 配置文件扫描机制

`battle_v3_runner.q` 启动时通过 `zm.DirScan` 依次扫描以下目录：
1. `/sdcard/MobileAnJian/Script/`
2. `/storage/emulated/0/MobileAnJian/Script/`

**规则**：检索文件名包含 `battle_v3_config` 的 `.mq` 编译文件。若未找到，直接终止执行并输出 `CONFIG PATH NOT FOUND`。

### 6.2 常见错误与处理

| 错误信息 / 现象 | 产生原因 | 解决方法 |
| :--- | :--- | :--- |
| `CONFIG PATH NOT FOUND` | 手机中未找到编译后的 `battle_v3_config` 文件 | 在按键精灵 PC 端打开 `battle_v3_config.q` 并点击「保存并同步」到手机 |
| `FRIEND CONFIG INVALID OR EMPTY, STOP` | 当前方案未配置助战，或关键字拼写不在支持列表中 | 检查对应方案的助战设置，确保填写为支持的关键字（如 `aobao`、`cdai` 等） |
| `CONFIG DSL EMPTY, STOP` | 当前方案的 DSL 动作字符串为空 | 在编辑器中为该方案添加技能/出牌动作后保存 |
| 编辑器无法保存 (Save Failed) | `server.py` 服务未运行或端口被占用 | 在终端启动 `python editor/server.py`，确认 8099 端口正常监听 |
| 误修改需恢复配置 | 误保存了错误配置需要回滚 | 在 `Q/.backup/` 目录找到对应时间戳快照文件，重命名覆盖回 `Q/battle_v3_config.q` |
