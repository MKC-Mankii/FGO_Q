# Runner 与配置文件说明（v4 版本）

本文档说明 FGO Q 脚本体系 **v4 版本架构**，涵盖 `battle_v4_runner.q`（战斗执行引擎）、`battle_v4_config.q`（战斗配置数据）以及配套的独立可视化配置编辑器（[editor_v4/](file:///F:/2nd%20Accra/Git/Github/FGO_Q/editor_v4)）。

---

## 1. v4 核心演进

相比 v3 版本，v4 版本完成了配置架构与交互深度的关键演进：

1. **5 项全局运行配置下放至 Config**：
   - 将原先深埋在 `runner.q` 中需要人工改代码的 5 项参数全部解耦并上移至 `battle_v4_config.q`：
     - `ACTION_GROUP_INDEX`（当前生效执行战场）
     - `BATTLE_COUNT`（连续战斗次数）
     - `APPLE_ENABLE`（是否自动吃苹果补充体力）
     - `MANUAL_CHOOSE_FRIEND`（是否人工手动选择助战）
     - `FORCE_COLOR_CARD`（是否强制选择对应色卡）
2. **Runner 引擎纯逻辑化与动态注入**：
   - `battle_v4_runner.q` 彻底移除硬编码初始值，启动时纯动态通过 `CfgGet` 从配置 mq 提取所有参数；
   - 强化兼容层：采用 `zm.FileRead`、`CLng` 与 `Time()` 适配最新按键精灵手机助手环境。
3. **极简高效的 V4 独立编辑器**：
   - 移除原版顶部冗余的战场选项卡栏（Tabs），将选战场与设默认归一化至顶栏「🎯 选择战场」下拉框；
   - 在顶栏直接集成 5 项运行参数的输入框与开关，免除了频繁打开代码文件改数字的繁琐操作；
   - 独立端口 `8098`，专属桌面应用快捷方式 `FGO_Config_Editor_V4.lnk`，与 V3 编辑器完全物理隔离、互不冲突。
4. **ADB 毫秒级直推与 10 秒心跳自动补推 (阶段一完成)**：
   - 彻底免去手工复制粘贴代码至 PC 手机助手的痛点，按 `Ctrl + S` 约 200ms 内全自动推送至模拟器与 PC 助手；
   - 前端 10 秒轻量心跳监测，若保存时模拟器离线，将在模拟器启动连接后自动补推最新配置。

## 2. 核心文件体系与链路

### 2.1 文件分工

- `Q/battle_v4_runner.q`：**战斗执行主脚本**
  - 负责图像识别、点击交互、出牌判定、轮次循环与异常处理；
  - 启动时优先读取 `/sdcard/FGO_Q/battle_v4_config.mq` 规范化总线配置，未找到时降级扫描历史工程；
  - 不含任何业务硬编码配置。
- `Q/battle_v4_config.q`：**战斗配置源文件**
  - 包含 5 项全局运行参数声明与全部 5 大战场、各方案的 DSL 动作串；
  - 供可视化编辑器直接读取与保存。
- `Q/.backup/`：**自动快照备份目录**
  - 编辑器每次保存时，自动将保存前的配置文件备份为 `battle_v4_config.q.YYYYMMDD_HHMMSS.bak.q`（自动保留最近 10 份快照）。
- `editor_v4/`：**Web 可视化编辑器 (v4 独立版)**
  - `server.py`：轻量本地服务，专职提供 v4 配置读写、快照备份与 ADB 同步 API（默认端口 `8098`）；
  - `adb_sync.py`：自动探测宿主机 ADB 路径（MuMu 等），负责将配置转为标准 GBK 编码直推下发；
  - `index.html` / `battle_config_editor.html`：编辑器页面（含专属 `[V4]` 徽标、参数工具栏与 ADB 状态胶囊）；
  - `css/` 与 `js/`：负责无 Tabs 单一下拉驱动的战场联动、DSL 解析、心跳监测与时序看板。

## 3. 全局运行配置规范

在 `battle_v4_config.q` 头部声明，且在 `editor_v4` 顶栏可直接实时调整：

| 字段名称 | 类型 | 可视化控件 | 说明 |
| :--- | :--- | :--- | :--- |
| `ACTION_GROUP_INDEX` | 整数 (0~4) | 🎯 选择战场（下拉框） | 指定当前生效的执行大组：`0=test`, `1=campaign`, `2=caber`, `3=grand`, `4=ordeal` |
| `BATTLE_COUNT` | 整数 (≥1) | ⚔️ 连战（数字输入框） | 连续执行战斗轮次计数，默认 `30` |
| `APPLE_ENABLE` | 布尔 (0/1) | 🍎 吃苹果（勾选框） | 体力耗尽时是否自动吃金/银苹果补充体力 |
| `MANUAL_CHOOSE_FRIEND` | 布尔 (0/1) | 🤝 人工助战（勾选框） | 是否跳过助战特征找图，等待人工点选助战 |
| `FORCE_COLOR_CARD` | 布尔 (0/1) | 🎨 强制色卡（勾选框） | 是否在打手出宝具时严格要求匹配克制色卡 |

## 4. 战域体系与 DSL 语法

### 4.1 战域分组对照

- **大组 0: test（测试战场）**：用于新方案验证与调试
- **大组 1: campaign（活动关卡）**：活动 90+/90++ 专属阵容
- **大组 2: caber（术呆通用）**：常规蓝卡冲浪队
- **大组 3: grand（戴冠战关卡）**：戴冠战高难/特攻队伍
- **大组 4: ordeal（白纸化地球）**：极速日常极星刷取

### 4.2 DSL 语法规则

每个方案通过分号 `;` 分隔回合（Wave），回合内部通过竖线 `|` 划分操作步：
```
s20, 30 | m22 | t1 | a7, 8, 5
```
- **从者技能 `s<slot><skill>`**：如 `s20` 表示 2 号位从者放第 1 技能；`s13` 表示 1 号位放第 3 技能并指定充能目标 3 号位。
- **御主礼装技能 `m<skill>` / `m<front><back>`**：如 `m22` 表示御主 2 号技能指定给 2 号位从者；`m30024` 表示战斗服 3 号换人技能（前排 2 号换后排 4 号）。
- **选择敌方目标 `t<target>`**：如 `t1` 选最左侧怪，`t2` 中间，`t3` 右侧。
- **出牌 `a<c1>, <c2>, <c3>`**：
  - 宝具位：`a6`（1 号从者宝具）、`a7`（2 号从者宝具）、`a8`（3 号从者宝具）；
  - 普卡位：`1~5`（物理卡位）或 `B, Q, A`（按色卡偏好找卡）。

## 5. 可视化编辑器（独立桌面应用）使用指南

### 5.1 启动与关闭

- **一键桌面启动（推荐）**：
  - 双击桌面或项目根目录下的 **`FGO_Config_Editor_V4.lnk`** 快捷方式（Saber 图标），直接以原生桌面独立窗口启动（基于 WebView2 引擎，窗口自适应 1600×1020），不依赖常规浏览器窗口。
  - 亦可双击 `editor_v4/start_editor.bat` 或 `editor_v4/start_editor.vbs` 备用启动。
- **一键退出关闭**：
  - **窗口右上角 `×` 关闭**：窗口关闭时自动清理端口与子进程，零后台残留；
  - **脚本备用退出**：双击运行 `editor_v4/stop_editor.bat`。
- **手动命令行启动**：
  ```bash
  python editor_v4/launcher.py
  ```
  纯 Web 调试模式（端口 `8098`）：
  ```bash
  python editor_v4/server.py
  ```

1. **顶栏运行配置一体化**：
   - 切换「🎯 选择战场」下拉框即同步切换左侧方案列表和中央看板，同时该战场即为脚本执行的生效战场；

## 6. 常见问题排查 (Troubleshooting)

| 异常现象 | 可能原因 | 解决方案 |
| :--- | :--- | :--- |
| `CONFIG PATH NOT FOUND` | 模拟器中未找到配置 mq 文件 | 打开 V4 编辑器点击保存（或点顶栏 `[📱 模拟器在线]` 徽标一键同步），或确认模拟器已开启 |
| `FRIEND CONFIG INVALID` | 当前方案助战拼写错误 | 检查方案的助战填写（如 `aobao`, `cdai`, `rba`, `cba`, `keli` 等） |
| 顶栏显示 `📱 模拟器离线` | 模拟器尚未开机或 ADB 掉线 | 打开 MuMu 模拟器等待就绪，前端将每隔 10 秒自动检测连接并自动补推配置 |
| 编辑器显示端口被占用 | 8098 端口有未退出的残留进程 | 双击运行 `editor_v4/stop_editor.bat` 或在任务管理器结束 pythonw 进程 |
| 配置误改需要恢复 | 误修改了重要方案 | 打开 `Q/.backup/` 目录，挑选最近时间戳的 `.bak.q` 覆盖回 `Q/battle_v4_config.q` |

## 7. Runner 底层控制流与战斗判定机制

`battle_v4_runner.q` 内部采用单一职责与统一守卫函数的状态机模型：

1. **统一前置回合守卫 (`WaitRoundReadyOrBattleEnd`)**：
   - 核心等待与就绪检测逻辑收敛在 `DoBattle -> DoGroupActions` 入口之前统一调度；
   - 各执行单元（`DoSkillActions` 从者技能、`DoMasterActions` 御主技能、`DoAttackActions` 选卡出牌）专职负责动作释放，动作完成后即刻返回，不再各自挂起等待战斗推进。
2. **战斗结束与结算检测触发约束**：
   - **触发前提**：仅当上一动作组确实完整执行了攻击出牌（Attack）动作后，下一组开始前的 `WaitRoundReadyOrBattleEnd` 才会激活战斗结束与领奖结算判定；若上一组仅为纯技能施放或御主换人，则严禁触发结束检测。
3. **领奖图色抗误判容错**：
   - 战斗动画与转场中，部分结算图色特征（如 `AWARD_TIE` 领奖图标）偶有发生瞬态噪点误识别；
   - 引擎内置了**回合检测宽限缓冲**、**多帧连续稳定采样确认**以及**领奖等待超时兜底**，防止因动画干扰提前误退战斗或结算卡死。
