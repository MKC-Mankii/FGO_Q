本文档是 FGO_Q 自动化体系 **v4 架构、通信总线与配置系统** 的官方权威技术指南与工程手册。全面涵盖 `battle_v4_runner.q`（战斗执行引擎）、`battle_v4_config.q`（策略配置与战术 DSL）、配套独立桌面/Web 可视化配置编辑器（[editor_v4/](file:///F:/2nd%20Accra/Git/Github/FGO_Q/editor_v4)）的完整系统设计、技术选型演进、通信总线协议、页面直控交互及按键移动端底层稳定性规范。

> [!NOTE]
> 关于 PC 手机助手、安卓模拟器与移动端按键精灵底层工具的机制说明、打包交互与环境避坑指南，请参阅 [docs/tools_and_runtime_architecture.md](file:///f:/2nd%20Accra/Git/Github/FGO_Q/docs/tools_and_runtime_architecture.md)。

## 1. 架构总览与演进哲学

### 1.1 背景与核心痛点
在 FGO_Q v3 及更早版本中，用户调整战斗策略与日常运行面临三大严重痛点：
1. **人工复制粘贴繁琐**：每次在可视化编辑器中调整技能顺序或参数，都必须全选、复制，再切换到 PC 端按键精灵手机助手中粘贴覆写。
2. **跨软件窗口切换断层**：频繁在浏览器/编辑器、代码工具、PC 手机助手、安卓模拟器之间来回切屏，操作链路冗长割裂。
3. **缺乏状态与反馈一体化**：在 Web 页面上无法直观感知战斗是否处于运行状态、当前进行到第几轮第几面、何时完成或为何中断。

### 1.2 核心解耦原则：业务策略与执行引擎彻底解耦
传统自动化的痛点根源在于：以往将“战斗代码（Runner）”与“策略配置（Config）”强行打包在一起。
- **Runner（战斗执行引擎）**：包含图色找图、特征识别、状态判定与容错算法。版本稳定后**极少变更**。
- **Config（策略配置）**：包含队伍出牌、从者技能释放、御主礼装、打手选择与连战次数。日常**频繁调优变更**。

**破局核心**：将 Config 彻底解耦为轻量独立文本，日常只传输策略配置，Runner 仅作为常驻宿主动态读取配置，从而完全消除对 PC 助手的日常依赖。

### 1.3 技术动线与架构选型对比
在确定 v4 页面直控方案前，团队对 Windows 宿主、ADB 通信桥以及安卓模拟器文件系统进行了底层实地探测，确认了以下关键事实：
- **`.mq` 文件本质为 GBK 明文脚本**：模拟器内部集成了解释器，可直接加载执行明文代码。
- **附件包 `.atc` 具备静态稳定性**：模拟器中已存在编译好的 `fgo_battle_v3_runner(...).atc`（约 186KB，封装了所有图片资源与紫猫插件），只要不引入全新图片特征，该包在模拟器内长期有效，**无需每次重新打包**。
- **按键助手协议逆向不可取**：按键官方未提供独立 CLI 编译器；PC 助手与模拟器的私有 Socket 调试协议极易随版本破坏，脱机全自动打包生成工程包代价巨大。

基于实地探测，团队对比了四种技术实现路线：

| 方案 | 运行机制 | 核心原理 | 优势 | 局限与取舍 | 决策 |
| :--- | :--- | :--- | :--- | :--- | :---: |
| **方案 A：常驻待命 + 文件指令总线** | 脚本挂机监听 Web 命令 | Runner 启动后进入 Idle 待命循环，Web 端通过 ADB 毫秒级写入 `cmd.txt = START` 触发 | 响应极快（<0.1s）、支持实时状态与日志回传、无需逆向私有协议、日常彻底脱离 PC 助手 | Runner 需引入常驻待命循环（已实现） | **采用 (首选路线)** |
| **方案 B：ADB 物理/快捷键唤醒** | 模拟物理按键触发冷启动 | 保存后覆写 `.mq`，通过 ADB 发送音量键或模拟点击悬浮球 | 每次均为冷启动，Runner 无需改造外层循环 | 会唤起系统音量条，且无法唤醒非前台挂起进程 | 淘汰 |
| **方案 C：PC 助手 UI 自动化** | 模拟人工键鼠操作助手 | 覆写本地 `.mq`，通过 Windows API 激活助手窗口发送 `F5` 调试 | 保留 PC 助手原汁原味的使用界面 | 运行期 PC 桌面必须保持开启助手窗口，存在焦点干扰 | 淘汰 |
| **方案 D：独立小精灵 APK 封装** | 打包为独立 Android App | 在助手内一次性打包导出为独立 APK 安装，Web 借助 `am start` 唤起 | 完全脱离按键手机版宿主 | 免费打包可能带启动确认弹窗；修改 Runner 需重新打包安装 | 淘汰 |

### 1.4 v4 全景特性概览
FGO_Q v4 正式基于「方案 A」全面构建，实现了以下系统性飞跃：
1. **5 项全局运行配置下放至 Config**：战场选择、连战轮次、吃苹果、手动助战、强制色卡全面解耦至配置层，可在界面实时调整并直接落盘。
2. **免复制直推与 10 秒轻量心跳自动补推**：保存时约 200ms 内全自动推送至模拟器与 PC 助手；离线期间修改配置在模拟器就绪后全自动静默补推。
3. **文件指令总线与网页直控启停**：在 Web 页面直接一键「▶ 运行战斗」与「⏹ 停止战斗」，按钮 100% 自动自愈还原，未启动友好拦截引导。
4. **内存热重载机制 (Zero Restart)**：脚本收到启动指令自动执行 `ReloadConfig()`，清空旧内存并重新读取最新配置，日常修改方案**完全无需重启按键脚本**。
5. **右下角无蒙层极简监控浮层**：点击顶栏状态胶囊展开，每秒高保真拉取模拟器按键调试日志，不添加全屏蒙层，页面操作零阻碍。
6. **Editor 本地轮转日志体系**：内置 5MB 轮转与高频请求静默过滤，保障问题排查清晰高效。

## 3. 多端协同保存与自动补推机制

### 3.1 一键保存（`Ctrl+S`）四重目标落盘规范
当在 Editor 中按下 `Ctrl+S` 或点击「💾 保存配置」时，后端在约 200ms 内原子化完成四重同步：
1. **代码仓库源文件**：落盘写入 `Q/battle_v4_config.q`；
2. **版本保护历史快照**：自动在 `Q/.backup/` 目录下生成带有高精度时间戳的备份文件（如 `battle_v4_config_20260925_160000.bak.q`），固定只滚动保留最近 10 份，防止误改无法撤销；
3. **模拟器通信总线目标**：直推至 `/sdcard/FGO_Q/battle_v4_config.mq`，这是 Runner 优先读取的配置路径；
4. **历史工程覆写（防脏读）**：同步覆写 `/sdcard/MobileAnJian/Script/fgo_battle_v4_config(...).mq`，彻底根除模拟器中残留的历史旧工程干扰；
5. **PC 手机助手目录对齐**：同步覆写 Windows 本地 PC 助手的工程目录，彻底防止用户未来切回 PC 助手误按 F5 冲掉新配置。

### 3.2 10 秒轻量心跳与条件自动补推状态机
为保证在“模拟器尚未开机时修改了配置，随后开机使用”场景下配置依然能保持一致，系统设计了优雅的补推状态机：
- **极轻量探测**：前端每隔 10 秒发起一次连通性轮询（`/api/adb/status`），ADB 状态采样耗时仅约 **20ms**，绝不占用系统与网络资源。
- **状态机严密约束（条件自动补推）**：
  - **无盲目推送**：不是模拟器一在线就无脑 ADB push；
  - **待补推标记（`pending_push`）**：只有当用户在模拟器离线期间执行过保存操作时，后端才会置位待补推标记；
  - **上线自动补推**：一旦心跳探测到模拟器重新就绪，后端立即自动执行补推，并清除该标记，前端弹出友好静默提示；
  - **日志高频静默**：心跳请求在 `editor.log` 中被智能过滤，日志中仅在触发补推时记录清晰明细。

## 4. 双向通信总线协议与运行时状态机

所有 Web 宿主与模拟器执行脚本之间均通过 `/sdcard/FGO_Q/` 规范化目录解耦交互。

### 4.1 下行指令总线 (`/sdcard/FGO_Q/cmd.txt`)
- **写入方**：Editor 后端（通过 `POST /api/runner/command` 由 ADB 极速写入）。
- **消费方**：Runner 执行脚本。
- **指令规范**：
  - **`START`**：通知脚本启动战斗。Runner 待命循环捕获后，立即将该文件内容覆写为空，并调用 `ReloadConfig()` 热重载配置后投入战斗。
  - **`STOP`**：通知脚本紧急停止战斗。Runner 在选助战、等待开局、回合就绪、领奖结算等关键守卫点检测到后，清空文件并安全退出当前循环，退回待命。
  - **空文本 / 文件不存在**：无控制操作。

### 4.2 上行状态总线 (`/sdcard/FGO_Q/status.txt`)
- **写入方**：Runner 执行脚本。
- **读取方**：Editor 后端（通过 `GET /api/runner/status` 轮询）。
- **文件格式**：标准的 Key-Value 属性行格式：
  ```ini
  state=RUNNING
  round=2
  total_rounds=30
  sub_round=3
  action=释放从者2技能1
  time=1727236800
  msg=正在进行第 2/30 轮战斗 (W3)
  ```
- **核心状态定义 (`state`)**：
  - `IDLE`：待命挂机中，正在静默轮询指令，绝不扰动游戏画面；
  - `RUNNING`：战斗正在执行中；
  - `STOPPING`：正在响应停止请求，进行资源释放与状态复位；
  - `OFFLINE`：脚本未启动或心跳超时（由后端动态判定）。

### 4.3 模拟器 Epoch 时间戳比对防假在线算法
若模拟器中残留着几天前的历史 `status.txt`，直接读取文件内容可能导致前端显示虚假的“待命中”。为此，`adb_sync.py` 实现了精准的时间戳校验算法：
1. **获取时间对齐基准**：
   - 通过 ADB 获取模拟器系统的 Linux Epoch 当前时间戳（`now_ts`）；
   - 通过 ADB 获取 `/sdcard/FGO_Q/status.txt` 的最后文件修改时间（`mtime`）。
2. **分级动态超时门限**：
   - **待命状态门限（`IDLE`）**：脚本待命时每隔约 3 秒刷新一次心跳。若 `now_ts - mtime > 12 秒`，判定脚本已在模拟器中被手动停止或退出。
   - **战斗状态门限（`RUNNING`）**：战斗中由于宝具动画、找图重试或关卡加载，可能偶有数十秒无状态变动。门限放宽至 **40 秒**；若超 40 秒无刷新，判定脚本已异常挂起或闪退。
3. **状态计算结论**：
   - 差值在门限内：判定 `alive = True`，状态取文件内记录的 `state`；
   - 差值超出门限：强制修正为 `alive = False, state = 'OFFLINE'`，上报描述 `脚本已停止或退出 (最后活跃于 Xs 前)`。

## 5. Web 页面直控交互与按钮自愈模型

前端页面（[editor_v4/index.html](file:///f:/2nd%20Accra/Git/Github/FGO_Q/editor_v4/index.html)）遵循状态单一真实源（Single Source of Truth）设计，杜绝页面按钮与真实运行状态出现任何不同步。

### 5.1 未启动前置拦截引导 (Pre-flight Guard)
当状态检测为 `OFFLINE` 时，用户若误触「▶ 运行战斗」，前端立即进行安全阻断，并弹出引导 Toast：
> ⚠️ **脚本未启动或已停止！**  
> 请先在按键精灵手机助手中按 F5，或在模拟器按键精灵 APP 中启动 battle_v4_runner 后再点击运行。

有效防止向离线环境抛出无效控制指令。

### 5.2 运行与安全优雅停止
- 运行中时，顶栏按钮平滑切换为醒目的红色「⏹ 停止战斗」；
- 用户点击停止时，前端发出 `STOP` 指令，状态切换为“正在停止...”；
- 脚本在下一个安全动作节点安全收敛后复位为待命。

### 5.3 按钮 100% 自动自愈还原
无论发生下列哪种情况，控制按钮都无需手动刷新页面，**100% 自动还原为就绪状态**：
- **Web 端主动停止**；
- **达到设定轮次（`BATTLE_COUNT`）打满自然退出**；
- **模拟器内手动停止脚本、按键悬浮窗关停或 APP 闪退**。

只要后端报告状态脱离 `RUNNING`（进入 `IDLE` 或 `OFFLINE`），前端的停止按钮瞬间隐藏，「▶ 运行战斗」自动复位就绪。

### 5.4 脚本运行监控面板规范
- **单一入口与层级分工**：
  - 顶栏常驻的「脚本运行状态胶囊」（`#runnerIndicator`）是**唯一全局真实源**，实时显示状态与轮次；
  - 点击胶囊可随时展开/收起右下角极简监控浮层（Toggle 切换），面板定位为**可选的补充调试终端**。
- **无蒙层零阻碍原则**：
  - 面板采用右下角固定浮动定位（`position: fixed`），**绝不添加任何全屏半透明遮罩**；
  - 浮层展开时，用户依然可以自由在页面上修改方案、切换战场、拖拽指令、调整参数并按 `Ctrl+S` 保存，所有交互完全畅通。
- **微型紧凑排版**：
  - 首行由状态图标（🟢/⚔️/⏳/⚪）引导紧随同步时间 `HH:MM:SS` 与战斗轮次，右侧微型虚浮嵌入「🔄 刷新」、「⏹ 停止」（战斗中呈现）与「✕ 收起」按钮；
  - 展开状态下**以 1 秒 1 次的高频自动拉取最新按键精灵调试日志**，代码框自动滚至最新输出；
- **不扰民原则**：
  - 点击「▶ 运行战斗」时**绝不自动强行弹开监控面板**，其展示完全交由用户主动点击掌控。

## 6. Runner 执行引擎底层设计与避坑规范

`battle_v4_runner.q` 是运行在移动端按键精灵宿主内的核心引擎，针对移动端解析器的脆弱性与长时间挂机稳定性进行了全面重构。

### 6.1 `MainStandbyLoop` 与 `ReloadConfig` 内存热重载 (Zero Restart)
- **常驻待命循环 (`MainStandbyLoop`)**：
  - 脚本启动后立即进入微秒级轮询，挂机监测 `/sdcard/FGO_Q/cmd.txt`；
  - 挂机期间绝不产生任何点击或触控扰动，保持极低 CPU 占用与每 3 秒一次的静默心跳上报。
- **动态内存热重载 (`ReloadConfig`)**：
  - 当捕获到 `START` 时，自动调用 `ReloadConfig()`；
  - 清空内存中现存的所有旧战场方案数组与全局变量；
  - 动态重新执行 `File.Read` 载入 `/sdcard/FGO_Q/battle_v4_config.mq`，解析出最新的 5 项配置与策略数组；
  - **日常无论怎样修改阵容与方案，完全无需在模拟器中反复重启脚本！**

### 6.2 统一前置回合守卫与状态机收敛 (`WaitRoundReadyOrBattleEnd`)
- **集中状态守卫**：
  - 回合就绪检测、战斗结束判定与卡牌状态判断集中收敛在 `DoBattle -> DoGroupActions` 的总入口前；
  - 各具体执行单元（`DoSkillActions`、`DoMasterActions`、`DoAttackActions`）专职释放动作，执行完毕即刻退出，不再各自随意挂起等待。
- **触发条件约束**：
  - 仅当上一动作组确实执行了攻击出牌（Attack）后，下一组开始前的 `WaitRoundReadyOrBattleEnd` 才会激活战斗结束与领奖结算判定；若上一组仅为纯技能施放或御主技能，严禁触发结束检测。

### 6.3 结算与领奖图色抗噪点容错算法
- 战斗转场或结算动画中，领奖图色特征（如 `AWARD_TIE` 图标）偶有瞬态噪点误识别；
- 引擎内置了**回合检测宽限缓冲**、**多帧连续稳定采样确认**以及**领奖等待超时兜底**，防止因动画干扰提前误退战斗或结算卡死。

### 6.4 关键检查点安全退出防护
为确保随时点击「⏹ 停止战斗」都能瞬间平稳退回待命，在以下长耗时或循环节点均嵌入了 `CheckStopCommand()`：
1. `ChooseFriend` 选助战与滑动刷新循环；
2. `CheckFirstBattle2Start` 开局关卡等待；
3. `CheckNoImgAndTap2` 战斗结算点击循环；
4. `WaitAttack` 等待指令卡出现；
5. 回合间动画等待。

### 6.5 按键语法避坑与词法规范
按键精灵手机版内部编译器对语法极为敏感脆弱，开发与维护必须严格遵循以下避坑规范：
1. **严禁使用 `CLng`，全面改用 `Int`**：
   - 按键精灵手机版在处理较大数值或特定表达式时，调用 `CLng()` 会破坏内部词法符号栈，导致后续正常的 `If...End If`、`Sub...End Sub` 发生假性对称性缺失或诡异报错；
   - V4 已对 Runner 进行了全面清洗，所有类型转换统一使用 `Int()`，词法语法 0 错误 0 警告完全对称闭合。
2. **严格遵守语法检查排查规范**：
   - **检查语法阶段（无本地日志）**：在 PC 助手点击保存或语法检查时，PC 助手仅在图形界面提示错误，**不会写入本地磁盘日志，也不会推送到模拟器（模拟器无日志）**。在此阶段排查问题时，**严禁凭空盲猜代码，必须主动查看具体的错误行号与报错描述**。
   - **脱机运行阶段（ADB 直读日志）**：运行时排查问题，直接通过 ADB 提取模拟器内部 `/sdcard/com.cyjh.mobileanjian/log/` 下的最新日志。

系统无缝支持两种正交的工作流模式：

## 8. 全局运行配置规范与战术 DSL 语法

### 8.1 全局运行配置规范
在 `battle_v4_config.q` 头部声明，并在 `editor_v4` 顶栏可直接实时调整：

| 字段名称 | 类型 | 可视化控件 | 说明 |
| :--- | :--- | :--- | :--- |
| `ACTION_GROUP_INDEX` | 整数 (0~4) | 🎯 选择战场（下拉框） | 指定当前生效的执行大组：`0=test`, `1=campaign`, `2=caber`, `3=grand`, `4=ordeal` |
| `BATTLE_COUNT` | 整数 (≥1) | ⚔️ 连战（数字输入框） | 连续执行战斗轮次计数，默认 `30` |
| `APPLE_ENABLE` | 布尔 (0/1) | 🍎 吃苹果（勾选框） | 体力耗尽时是否自动吃金/银苹果补充体力 |
| `MANUAL_CHOOSE_FRIEND` | 布尔 (0/1) | 🤝 人工助战（勾选框） | 是否跳过助战特征找图，等待人工点选助战 |
| `FORCE_COLOR_CARD` | 布尔 (0/1) | 🎨 强制色卡（勾选框） | 是否在打手出宝具时严格要求匹配克制色卡 |

### 8.2 战域分组对照
- **大组 0: test（测试战场）**：用于新方案验证与调试
- **大组 1: campaign（活动关卡）**：活动 90+/90++ 专属阵容
- **大组 2: caber（术呆通用）**：常规蓝卡冲浪队
- **大组 3: grand（戴冠战关卡）**：戴冠战高难/特攻队伍
- **大组 4: ordeal（白纸化地球）**：极速日常白纸化极星刷取

### 8.3 DSL 语法规则
每个方案通过分号 `;` 分隔回合（Wave），回合内部通过竖线 `|` 划分操作步：
```
s20, 30 | m22 | t1 | a7, 8, 5
```
- **从者技能 `s<slot><skill>`**：如 `s20` 表示 2 号位从者放第 1 技能（无指定目标）；`s13` 表示 1 号位放第 3 技能并指定充能目标 3 号位。
- **御主礼装技能 `m<skill>` / `m<front><back>`**：如 `m22` 表示御主 2 号技能指定给 2 号位从者；`m30024` 表示战斗服 3 号换人技能（前排 2 号换后排 4 号）。
- **选择敌方目标 `t<target>`**：如 `t1` 选最左侧怪，`t2` 中间，`t3` 右侧。
- **出牌 `a<c1>, <c2>, <c3>`**：
  - 宝具位：`a6`（1 号从者宝具）、`a7`（2 号从者宝具）、`a8`（3 号从者宝具）；
  - 普卡位：`1~5`（物理卡位）或 `B, Q, A`（按色卡偏好找卡）。

## 9. 本地日志体系与排查维护 (Troubleshooting)

### 9.1 Editor 本地日志子系统
为保障配置编辑器的稳定性与可维护性，`editor_v4/` 内置了独立的本地日志子系统：
- **日志路径**：`editor_v4/logs/editor.log`；
- **文件轮转**：采用 `RotatingFileHandler`，单文件上限 **5MB**，自动轮转保留 **5 份历史归档**（`editor.log.1` ~ `.5`），超额自动清理；
- **字符编码**：全链路采用 **UTF-8** 编码写入，防止 Windows 本地 GBK 产生乱码；
- **智能静默过滤**：自动过滤高频心跳轮询（`/api/runner/status` 与 `/api/adb/status`），保持日志文件干净紧凑；
- **记录范围**：服务启动、配置保存与 `.backup/` 快照落盘、ADB 直推耗时、START/STOP 控制下发及所有未捕获异常的完整 Traceback。
- **版本控制**：已在根目录 [.gitignore](file:///f:/2nd%20Accra/Git/Github/FGO_Q/.gitignore) 中严格忽略 `logs/` 与 `editor_v4/logs/`，严防日志污染仓库。

### 9.2 移动端运行时日志提取与保留
- 运行中排查问题时，可直接通过 ADB 读取模拟器 `/sdcard/com.cyjh.mobileanjian/log/` 下的最新日志；
- 模拟器日志定期保留最近 3 天，系统会自动清除 3 天前的冗余日志。

### 9.3 常见故障与自愈指引速查表

| 异常现象 | 可能原因 | 解决方案 |
| :--- | :--- | :--- |
| 点击运行弹出“脚本未启动或已停止” | 模拟器中按键精灵脚本未处于待命状态 | 检查顶部状态徽标；在 PC 助手按 F5 或在模拟器内点击启动 `battle_v4_runner` |
| 点击停止按钮后没有立刻停下 | 脚本正在执行技能动画、选助战或换人 | 脚本在当前动作执行完的第一个检查点即会退出，等待 1~3 秒即可安全复位 |
| 顶栏显示 `📱 模拟器离线` | 模拟器尚未开机或 ADB 掉线 | 打开 MuMu 模拟器等待就绪，前端将每隔 10 秒自动检测连接并在恢复后自动补推配置 |
| 编辑器显示端口 8098 被占用 | 上一次退出的残留进程未杀干净 | 双击运行 `editor_v4/stop_editor.bat` 或在任务管理器中结束 python 进程 |
| 配置误改需要恢复历史版本 | 误操作覆盖了重要战术方案 | 打开 `Q/.backup/` 目录，挑选对应时间戳的 `.bak.q` 恢复至 `Q/battle_v4_config.q` |
| 模拟器端提示 `CONFIG NOT FOUND` | `/sdcard/FGO_Q/` 尚未下发配置 | 在编辑器中按一次 `Ctrl + S`，或点击顶栏模拟器在线徽标执行一次全量下发 |
| 监控面板日志出现中文乱码 | 编码未统一识别 | 确保使用最新版 `editor_v4`，日志读取通道已全链路强制 UTF-8 解码与回传 |
