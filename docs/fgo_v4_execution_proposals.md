# FGO_Q v4 页面直控运行方案与思考动线

本文档记录针对 **“在 Config Editor 页面上直接运行按键精灵脚本”** 的架构思考、实地底层技术探测发现、不同技术路线的对比与最终落地规划。

---

## 1. 目标与核心诉求

- **目标**：在 Web Config Editor（或桌面编辑器窗口）中增加「▶ 运行战斗」与「⏹ 停止战斗」功能。
- **要解决的核心痛点**：
  1. **人工复制粘贴繁琐**：每次在 Web 调完配置或逻辑，都需要人工复制粘贴到 PC 端按键精灵手机助手中。
  2. **跨软件窗口切换断层**：需要频繁在浏览器、代码编辑器、按键精灵手机助手之间来回切换。
  3. **缺乏状态与反馈一体化**：在 Web 上无法直观感知战斗是否正在运行、当前处于哪一轮、何时结束。

---

## 2. 关键底层探测事实

在确定技术路线前，通过对本地环境与安卓模拟器进行了实地 ADB 与文件系统探测，确认了以下关键技术事实：

1. **`.mq` 文件本质为明文代码**：
   - 模拟器 `/sdcard/MobileAnJian/Script/` 和 PC 助手本地目录下的 `.mq` 文件，均为标准 GBK 编码明文文本文件。
   - 安卓端“按键精灵手机版”内部集成了解释器，可以直接加载并执行文本格式的 `.mq` 代码。
2. **附件包 `.atc` 具备静态稳定性**：
   - 模拟器中已存在当前版本的 `fgo_battle_v3_runner(...).atc`（约 186KB，封装了所有图片特征 `Attachment:*.png` 及紫猫插件）。
   - 只要不新增全新的特征截图，`.atc` 附件包在模拟器中长期有效，**无需每次运行重新生成或传输**。
3. **Runner 具备运行期动态读写能力**：
   - Runner 启动时通过 `File.Read` 动态载入配置。因此，**配置数据无需与 Runner 打包在一起，可随时通过外部写入并实现热生效**。
4. **模拟器端环境常驻可用**：
   - 模拟器已处于 ADB 连接状态（`emulator-5554`），按键精灵手机版（`com.cyjh.mobileanjian`）及其 root 执行进程常驻运行中。

## 3. 路线分水岭：跳过助手 vs 保持链路 vs 解耦总线

### 3.1 为什么“完全跳过助手脱机生成工程包”不可取？

“脱离按键助手，直接在 Web 端全自动生成 `.mq`/`.atc`/`.lc` 并直接命令模拟器唤起原生引擎”在工程上极难成立：
- **无官方独立 CLI 编译器**：按键官方未公开脱机编译器，无法在 Python 纯脱机环境下生成带签名的完整工程。
- **私有通信协议成本高**：手机助手点击调试时走的是专用 Socket 协议，逆向成本巨大且极其脆弱，模拟器环境或版本变动极易崩溃。

### 3.2 破局关键：逻辑与配置“彻底解耦”

**痛点的真正根源在于：以往将“战斗代码（Runner）”与“策略配置（Config）”强行捆绑在了一起。**
- Runner（逻辑代码、图色识别、找图算法）：版本稳定后**很少频繁变更**。
- Config（队伍出牌、技能释放、打手助战）：玩家日常**频繁调优变更**。

只要将配置抽离为纯文本，由 Web 借助 ADB 毫秒级直推，日常运行即可完全免去对 PC 助手的编译与打包依赖。

## 4. 四大候选方案动线分析

基于以上事实，梳理出四种可行的技术动线：

| 方案 | 运行机制 | 核心原理 | 优点 | 缺点 / 限制 | 推荐度 |
| :--- | :--- | :--- | :--- | :--- | :---: |
| **方案 A：常驻待命 + 文件指令总线** | 脚本挂机监听 Web 命令 | Runner 在模拟器启动后进入 Idle 轮询，Web 点击运行通过 ADB 写入 `cmd.txt = START` 触发 | 响应极快（<0.1s）、支持实时日志与状态回传、无需破解按键协议、日常彻底脱离 PC 助手 | 需要在 Runner 中增加简单的指令等待外层循环 | ⭐⭐⭐⭐⭐ *(首选)* |
| **方案 B：ADB 物理/快捷键唤醒** | 模拟物理按键触发冷启动 | Web 端保存后直接覆盖更新模拟器里的 `.mq`，通过 ADB 发送音量键或模拟点击悬浮球启动 | 每次均为冷启动，Runner 保持原始结构无需大改 | 模拟器端需保持按键悬浮窗或音量键监听开启 | ⭐⭐⭐⭐☆ |
| **方案 C：PC 端按键助手 UI 自动化** | 模拟人工键鼠操作助手 | Web 后端自动覆写 PC 助手目录的 `.mq`，通过 Windows API 向助手窗口发送保存与 `F5`（调试）| 完全保留 PC 助手原汁原味的使用流程与调试日志窗口 | 运行时 PC 桌面必须保持开启按键助手窗口，偶有焦点干扰 | ⭐⭐⭐☆☆ |
| **方案 D：独立小精灵 APK 封装** | 打包为独立 Android App | 在助手内将脚本一次性打包导出为独立 APK 安装，Web 借助 `am start` 原生拉起 | 完全脱离按键助手与手机版 | 免费打包可能带启动确认弹窗；若修改 Runner 核心逻辑需重新打包安装 | ⭐⭐⭐☆☆ |

## 5. 推荐演进方案详解（方案 A：文件指令总线架构）

### 5.1 完整数据与指令流转图

```text
┌─────────────────────────────────────────────────────────────┐
│                 Web Config Editor 前端页面                  │
│       [ 💾 保存配置 ]    [ ▶ 运行战斗 ]    [ ⏹ 停止 ]       │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTP 请求 (POST /api/run)
┌──────────────────────────────▼──────────────────────────────┐
│                 editor_v4/server.py 本地后端                 │
│   1. 将 Web 当前方案生成纯文本配置                            │
│   2. 执行: adb push config.txt /sdcard/MobileAnJian/Script/  │
│   3. 执行: adb shell "echo START > /sdcard/FGO_Q/cmd.txt"    │
└──────────────────────────────┬──────────────────────────────┘
                               │ ADB 协议 (耗时 < 0.1秒)
┌──────────────────────────────▼──────────────────────────────┐
│                    安卓模拟器 (MuMu)                        │
│   文件: /sdcard/FGO_Q/cmd.txt (指令)                         │
│   文件: /sdcard/FGO_Q/status.txt (运行状态)                  │
│   文件: /sdcard/MobileAnJian/Script/...config.mq (最新配置)  │
└──────────────────────────────▲──────────────────────────────┘
                               │ File.Read / zm.FileRead
┌──────────────────────────────┴──────────────────────────────┐
│         模拟器按键精灵手机版: battle_v4_runner.mq            │
│   - 常驻后台待命 (Idle 状态)                                │
│   - 检测到 cmd.txt 为 START ➔ 载入最新配置 ➔ 执行战斗        │
│   - 战斗各回合向 status.txt 写入进度 ➔ 供 Web 前端拉取显示   │
│   - 战斗结束或收到 STOP ➔ 恢复为 IDLE 等待下一轮指令         │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 核心价值

1. **零人工复制粘贴**：Web 保存配置后，ADB 直接写入模拟器指定文件，毫秒级就绪。
2. **无需反复重启脚本**：按键精灵手机版只需在模拟器中启动一次，即可持续响应 Web 端的多次启动与停止请求。
3. **状态可感知**：Web 页面上不仅能发指令，还能展示战斗状态（空闲 / 战斗中 / 已完成）与实时输出日志。

## 6. V4 实施落地阶段规划

- **阶段零：代码与配置体系解耦 (已完成 ✅)**
  - 创建 `battle_v4_config.q` 与 `battle_v4_runner.q`；
  - 将 5 项写死在 Runner 中的手工配置彻底抽离至 Config 中，支持在编辑器中自由编辑；
  - 规范化双版本编辑器（`editor_v3/` 独立运行于端口 8099；`editor_v4/` 独立运行于端口 8098）；
  - V4 编辑器精简去除战场 Tabs，改由单一下拉框统一切换并展示 5 项全局运行配置。
- **阶段一：打通免复制与配置直推 (已完成 ✅)**
  - 实现 `editor_v4/adb_sync.py` 自动化检测与推送模块（内置 MuMu / 按键自带 ADB 路径自动探测与设备健康自愈）；
  - `editor_v4/server.py` 在执行保存（`POST /api/save`）与手动同步（`POST /api/sync`）时：
    - **代码仓库源文件**：落盘保存至 `Q/battle_v4_config.q`（自动保留最近 10 次历史快照）；
    - **模拟器通信总线**：下发至规范化通信目录 `/sdcard/FGO_Q/battle_v4_config.mq`；
    - **历史工程防脏读**：覆写模拟器历史工程文件 `/sdcard/MobileAnJian/Script/fgo_battle_v4_config(...).mq`；
    - **PC 手机助手同步**：覆写 Windows 本地 PC 助手工程目录（防误点 F5 冲掉新配置）；
    - *(已移除冗余的 `/sdcard/MobileAnJian/Script/battle_v4_config.mq` 备份)*；
  - 前端顶部集成 `[📱 模拟器在线 (emulator-5554)]` 状态胶囊，保存时毫秒级（约 200ms）反馈直推成果；
  - **10 秒轻量心跳与条件自动补推**：
    - 前端每隔 10 秒发起一次极低开销（耗时仅 ~20ms）的轻量连通性检测；
    - 状态机精准约束：**只有当保存过且当时模拟器未连接（存在待补推标记）时，才会在模拟器恢复在线后自动触发一次补推**；
    - 代码仓库源文件与本地 PC 助手的保存完全不依赖模拟器，随时保持双向对齐；
  - `battle_v4_runner.q` 引入优先读取 `/sdcard/FGO_Q/battle_v4_config.mq` 机制，彻底闭环免复制热生效。
- **阶段二：Runner 增加待命与指令响应（下一阶段目标）**
  - 在 `battle_v4_runner` 中添加简短的待命外层循环（监听 `cmd.txt`）。
  - 在 Web 页面添加「▶ 运行战斗」与「⏹ 停止战斗」按钮，打通网页直控启停闭环。
- **阶段三：界面交互与状态看板优化**
  - Web 端右下角集成轻量“运行日志与状态面板”，支持实时查看 Wave 进度与战斗日志流。
