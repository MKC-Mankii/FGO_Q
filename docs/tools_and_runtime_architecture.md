## 2. PC 按键精灵手机助手

### 2.1 定位与职责
- **官方 Windows 客户端**：按键精灵官方提供的 Android 移动端脚本集成开发环境（IDE）。
- **工程资产管理**：管理脚本源码、界面配置（`.prop` / `.uis`）以及图色资源附件（`.atc`）。
- **调试连接桥梁**：负责与模拟器（或真机）建立连接，将脚本分发下发至移动端并捕获调试日志。

### 2.2 本地工作空间文件结构
PC 手机助手的脚本工作目录位于 Windows 本地路径：
`D:\ProgramData\按键精灵\按键精灵手机助手\Script\`

每个脚本工程均以其工程名称与内部生成的 GUID 组合命名：
- **`*.mq`**：按键精灵脚本源码（采用 Windows **GBK** 编码，CRLF 换行）。
- **`*.atc`**：附件资源压缩包（包含 `Attachment:` 找图用的全部小图素材，以及紫猫插件 `zm.luae`）。
- **`*.lc`**：按键精灵手机助手编译生成的 Lua Bytecode 缓存。
- **`*.prop` / `*.uis`**：工程属性元数据与移动端配置界面描述。

### 2.3 调试下发与打包机制 (核心原理)
当开发者在 PC 助手界面中点击 **「调试」** 按钮（或按快捷键 **`F5`**）时，PC 助手会在后台执行以下标准动作：
1. **本地打包**：将当前编辑器内的脚本源码保存，并与工程所属的 `.atc` 附件包一起打包；
2. **ADB 推送传输**：通过 ADB 连接通道，将生成的 `*.mq` 与 `*.atc` 强行推送（`adb push`）至模拟器的 `/sdcard/MobileAnJian/Script/` 目录；
3. **唤起执行信号**：通过 Socket / Intent 向模拟器内运行的按键精灵守护进程发送“开始调试”指令；
4. **日志双向回传**：移动端脚本通过 `TracePrint` 打印的日志，会通过网络管道实时回传并渲染在 PC 助手的底部调试控制台中；
5. **结束退出**：脚本执行完毕或手动停止后，PC 助手控制台提示 `已退出调试模式`。

### 2.4 典型痛点与覆盖冲突 (Gotchas)
> [!WARNING]
> **PC 助手的“单向覆盖陷阱”**：
> PC 手机助手始终以 Windows 本地 `D:\ProgramData\按键精灵\...\Script\` 下的文件为**绝对权威源（Single Source of Truth）**。
> 
> 如果开发者或外部程序仅仅修改了模拟器端 `/sdcard/MobileAnJian/Script/` 中的配置或脚本，只要有人在 PC 助手里按下了 `F5`（或点击了保存/调试），PC 助手就会**毫不犹豫地将本地旧缓存打包并覆盖模拟器**，导致模拟器中的新配置瞬间被“冲回旧版”！
> 
> **应对原则**：任何涉及外部配置或脚本更新的工具链，必须同步保持本地 PC 助手工程目录与模拟器端的数据一致，或者将高频变动的数据完全抽离至按键精灵工作区以外的独立目录中（如 `/sdcard/FGO_Q/`）。

## 3. 安卓模拟器 (Android Emulator)

### 3.1 定位与环境
- **虚拟化运行容器**：本项目主要基于 **MuMu 模拟器（MuMu 12 / MuMu 6）**，运行 Android 操作系统与游戏本体（`com.bilibili.fatego`）。
- **ADB 宿主接口**：模拟器在宿主机暴露 ADB 调试服务端口（常见如 `127.0.0.1:5555`，设备标识形如 `emulator-5554`），自带独立 ADB 二进制程序（如 `D:\Program Files\Netease\MuMu\nx_main\adb.exe`）。

### 3.2 存储空间划分与权限
1. **公共存储空间 (`/sdcard/`，即 `/storage/emulated/0/`)**：
   - 全局可读写空间，无需复杂 Linux 提权即可通过 ADB 直接访问。
2. **按键精灵内部空间 (`/sdcard/MobileAnJian/`)**：
   - 按键精灵手机版及其 PC 助手专属空间，结构不可控，升级、清空缓存或重新打包容易受到干扰。
3. **规范化数据目录 (`/sdcard/FGO_Q/`)**：
   - 本项目专门开辟的独立存储目录；
   - 彻底脱离按键精灵的内部黑盒管理，免受 PC 助手打包覆盖干扰；
   - 作为外部配置读取与进程间总线交互的标准文件存储位置。

## 4. 模拟器中的按键精灵 (Mobile AnJian)

### 4.1 定位与系统结构
- **执行宿主 App**：安装在模拟器中的 Android 应用（`com.cyjh.mobileanjian`）。
- **底层 Root 守护进程**：按键精灵启动后会生成具有 Root 权限的守护子进程（如 `com.cxrjn.apjzj:knjpj`），获取系统底层的截屏快照、虚拟触控（Input Tap/Swipe）及物理按键注入权限。

### 4.2 两种运行方式对比

| 维度 | PC 助手调试运行模式 | 模拟器脱机运行模式（APP / 悬浮球） |
| :--- | :--- | :--- |
| **触发载体** | PC 端按键精灵手机助手界面（F5） | 模拟器内部按键精灵 APP 列表或屏幕悬浮小狮子 |
| **PC 助手依赖** | 强依赖（必须打开 PC 助手且保持连接） | 完全不依赖（PC 助手可直接关闭） |
| **脚本来源** | PC 助手每次点击调试时实时打包下发 | 读取模拟器内部 `/sdcard/MobileAnJian/Script/` 留存工程 |
| **日志查看** | PC 助手底部控制台实时输出 | 模拟器悬浮窗提示，或直接抓取模拟器本地日志 |
| **日常适用度** | 适合找图与底层语法断点调试 | 适合日常自动化常驻运行 |

### 4.3 核心依赖插件 (紫猫插件 `zm.lua`)
Runner 核心引擎重度依赖打包进 `.atc` 的紫猫插件（`zm.lua` / `zm.luae`），其主要赋能以下能力：
- **`zm.FindPic`**：高性能模糊找图、偏色匹配与多图并发检索；
- **`zm.DirScan`**：目录动态文件扫描与通配符过滤；
- **`zm.FileRead`**：大文本快速读取与配置字符串解析。

### 4.4 移动端运行时的技术边界与限制

在按键精灵移动端开发中，存在以下关键技术约束，决定了脚本的加载与架构设计：
1. **模块引用限制（`Import` 局限）**：
   - 按键精灵手机助手的 `Import` 语法仅支持引入打包在附件中的官方插件（如 `zm.luae`），无法直接通过 `Import` 动态加载或执行外部独立的 `.q` / `.mq` 逻辑脚本代码。
2. **附件包隔离限制（`.atc` 无法作为普通文件读取）**：
   - `.atc` 附件包是经加密压缩的资源包，内置函数 `File.Read` 或操作系统文件 API 只能读写 `/sdcard/` 等标准文件系统路径，无法把打包在 `.atc` 里的文本附件直接当普通文本文件按路径读出。
   - **架构对策**：因此配置无法直接内嵌在 `.atc` 中热更新，必须以外部独立文本文件（如 `/sdcard/FGO_Q/battle_v4_config.mq`）形式存放在模拟器标准存储区，并在脚本执行时通过 `zm.FileRead` 动态载入解析。

## 5. 模拟器按键精灵日志体系与排查规范

在脚本运行与调试过程中，日志是定位逻辑停滞与异常的核心依据。按键精灵具备双重日志输出路径：

### 5.1 双通道日志输出机制
- **通道一：PC 助手调试控制台（开发首选）**：
  - **触发条件**：在 PC 助手连接模拟器并按 F5 调试时。
  - **特点**：实时回传至 PC 助手底部控制台，适合断点观察与语法告警检查。
- **通道二：模拟器本地日志文件（排查兜底）**：
  - **存储路径**：`/sdcard/com.cyjh.mobileanjian/log/`（即 `/storage/emulated/0/com.cyjh.mobileanjian/log/`）。
  - **命名格式**：`YYYY-M-D-H-M-S.log`（例如 `2026-9-25-9-58-50.log`）。
  - **生成机制**：无论是 PC 助手 F5 调试，还是模拟器悬浮窗脱机运行，按键精灵只要执行 `TracePrint`，都会实时全量落盘至该目录。
  - **编码标准**：该日志文件采用 **UTF-8** 编码，外部程序读取时必须以 UTF-8 方式解码（禁止直接用 GBK 解码，否则汉字会变为乱码）。

### 5.2 免截图直接抓取排查流程 (ADB 终端直连)
当出现“脚本没报错但逻辑没走下去/卡死/闪退”等情况时，**严禁要求用户手动截图**，应优先通过 ADB 直接翻阅模拟器日志：
```bash
# 1. 查找模拟器中最新生成的日志文件 (按时间倒序)
adb -s emulator-5554 shell ls -lt /sdcard/com.cyjh.mobileanjian/log/ | head -n 5

# 2. 读取最新一份日志的内容 (直接查看 TracePrint 输出与异常阻断信息)
adb -s emulator-5554 shell cat /sdcard/com.cyjh.mobileanjian/log/2026-9-25-9-58-50.log
```

### 5.3 模拟器日志定期清理策略
- **历史堆积隐患**：按键精灵高频调试运行时会在该目录下快速生成成百上千个小日志文件，严重拖慢模拟器文件系统索引与磁盘空间。
- **运维规范**：维护模拟器日志时，**必须保留最近 3 天的日志（例如今日及前两日）**，将 3 天以前的陈旧日志全部清除。

### 5.4 无法获取日志的典型场景与交互规范 (严禁盲猜盲改)
在某些排查阶段，系统底层**根本不会生成任何文件日志**，必须严格遵循以下判断依据与操作准则：

- **典型无日志场景：PC 助手“检查语法 / 静态编译”阶段**
  - **PC 端无磁盘日志**：用户在 PC 助手点击“检查语法”时，由助手内置的前端解析器（`compile.lc`）执行纯内存静态词法分析。错误（如 `错误: 第115行: 参数个数不匹配。错误码=2489:66`）仅直接渲染在 PC 助手的弹窗与底部错误控件中，**绝不写入任何本地日志文件**。
  - **模拟器端完全无感知**：因为代码存在语法错误未通过编译，**脚本尚未打包，也未向模拟器下发执行**，模拟器本地日志目录 `/sdcard/com.cyjh.mobileanjian/log/` 自然没有任何新日志产生。
- **排查红线与行动规范**：
  > [!CAUTION]
  > **无日志时严禁擅自猜测与闷头改动！**
  > 当确定属于“检查语法出错”或“ADB 与本地均无日志产生”的阶段时，**外部工具或 AI 必须第一时间停下并主动向用户索取错误信息**（包括报错行号、错误码、提示文本或截图）。绝对禁止在没有确切日志支撑的情况下擅自臆测、闷头修改代码！

## 6. 核心资产同步边界（Config 可自动推 vs Runner 严禁自动同步）

在自动化体系中，必须严格遵守“配置层”与“执行引擎层”的权限与同步隔离红线：

| 资产类型 | 代表文件 | 同步策略 | 责任方与操作方式 | 设计原因与安全红线 |
| :--- | :--- | :--- | :--- | :--- |
| **策略配置 (Config)** | `Q/battle_v4_config.q` | **可由外部工具自动同步** | 工具保存时自动推送至 PC 助手工程与模拟器 `/sdcard/FGO_Q/` | 配置为纯数据，修改高频，自动同步消灭人工复制粘贴成本与版本漂移。 |
| **执行引擎 (Runner)** | `Q/battle_v4_runner.q` | **严禁外部程序自动同步**<br>(严格保持手工操作) | **由开发者人工在 PC 手机助手中复制代码、检查语法、按 F5 调试** | Runner 是核心执行引擎，涉及代码结构、图色特征绑定与编译。任何外部程序或 AI 擅自自动静默覆盖 PC 助手或模拟器的 Runner 文件，都可能破坏开发者正在调试的代码上下文或造成未编译事故。因此代码改动仅留在 Git 仓库，同步必须由人工操作。 |

## 7. 按键精灵移动端核心避坑指南（Hard Lessons Learned）

本章节记录在实战踩坑中确认的按键精灵移动端底层限制与编码规范：

### 7.1 词法限制：严禁使用 `CLng`（必须使用 `Int` 或 `CInt`）
- **现象**：在代码中调用 `CLng(val)` 时，PC 助手不仅不会提示“未定义函数”，反而在编译时抛出极其诡异的语法错误（如 `第115行: 参数个数不匹配。错误码=2489:66` 或后续变量 `名称 CurrentBattleCount 有重复。错误码=1035`）；
- **根本原因**：按键精灵移动端解释器底层**未注册 `CLng` 关键字**。当词法分析器遇到 `CLng` 时会破坏后续的语法符号栈，导致 parser 丢失当前的块上下文，从而将正常的下一行代码误识别为参数不匹配或重复声明；
- **编码铁律**：在按键精灵移动端脚本中，整型转换**一律使用 `Int(...)` 或 `CInt(...)`**。

### 7.2 空引用防护：找图循环返回 `null` 后的安全判空
- **现象**：当外部请求停止时，找图循环函数（如 `ContinuousCheckImg`）检测到停止信号后退出并返回 `null`，紧接着调用方直接执行 `Dim TapPointX = Point[1]`，导致脚本抛出空引用异常闪退；
- **防线规范**：所有接收找图坐标的地方，在访问数组下标前**必须前置判断**：
  ```vb
  Dim Point = ContinuousCheckImg(Target)
  If Point = null Or USER_STOP_REQUESTED Then
      Exit Function
  End If
  Dim TapPointX = Point[1]
  ```

### 7.3 死循环内部必须嵌入停止感知
- **原则**：所有包含 `Do While true` 的长时循环（包括开局等待 `CheckFirstBattle2Start`、选助战 `ContinuousCheckImg`、结算连续点击 `CheckNoImgAndTap2`），在循环体内部的第一行都必须显式调用：
  ```vb
  If USER_STOP_REQUESTED Or CheckStopSignal() Then
      Exit Do
  End If
  ```
  确保脚本在任何非战斗、等待或结算阶段均能毫秒级捕获停止指令，平稳退出回待命循环，绝不造成假死或卡死。
