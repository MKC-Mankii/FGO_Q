## 2. PC 按键精灵手机助手

### 2.1 定位与职责
- **官方 Windows 客户端**：按键精灵官方提供的 Android 移动端脚本集成开发环境（IDE）。
- **工程资产管理**：管理脚本源码、界面配置（`.prop` / `.uis`）以及图色资源附件（`.atc`）。
- **调试连接桥梁**：负责与模拟器（或真机）建立连接，将脚本分发下发至移动端并捕获调试日志。

### 2.2 本地工作空间文件结构
PC 手机助手的脚本工作目录位于 Windows 本地路径：
`D:\ProgramData\按键精灵\按键精灵手机助手\Script\`

每个脚本工程均以其工程名称与内部生成的 GUID 组合命名：
- **`*.mq`**：按键精灵脚本源码（采用 Windows **GBK** 编码，CRLF 换行）。
- **`*.atc`**：附件资源压缩包（包含 `Attachment:` 找图用的全部小图素材，以及紫猫插件 `zm.luae`）。
- **`*.lc`**：按键精灵手机助手编译生成的 Lua Bytecode 缓存。
- **`*.prop` / `*.uis`**：工程属性元数据与移动端配置界面描述。

### 2.3 调试下发与打包机制 (核心原理)
当开发者在 PC 助手界面中点击 **「调试」** 按钮（或按快捷键 **`F5`**）时，PC 助手会在后台执行以下标准动作：
1. **本地打包**：将当前编辑器内的脚本源码保存，并与工程所属的 `.atc` 附件包一起打包；
2. **ADB 推送传输**：通过 ADB 连接通道，将生成的 `*.mq` 与 `*.atc` 强行推送（`adb push`）至模拟器的 `/sdcard/MobileAnJian/Script/` 目录；
3. **唤起执行信号**：通过 Socket / Intent 向模拟器内运行的按键精灵守护进程发送“开始调试”指令；
4. **日志双向回传**：移动端脚本通过 `TracePrint` 打印的日志，会通过网络管道实时回传并渲染在 PC 助手的底部调试控制台中；
5. **结束退出**：脚本执行完毕或手动停止后，PC 助手控制台提示 `已退出调试模式`。

### 2.4 典型痛点与覆盖冲突 (Gotchas)
> [!WARNING]
> **PC 助手的“单向覆盖陷阱”**：
> PC 手机助手始终以 Windows 本地 `D:\ProgramData\按键精灵\...\Script\` 下的文件为**绝对权威源（Single Source of Truth）**。
> 
> 如果开发者或外部程序仅仅修改了模拟器端 `/sdcard/MobileAnJian/Script/` 中的配置或脚本，只要有人在 PC 助手里按下了 `F5`（或点击了保存/调试），PC 助手就会**毫不犹豫地将本地旧缓存打包并覆盖模拟器**，导致模拟器中的新配置瞬间被“冲回旧版”！
> 
> **应对原则**：任何涉及外部配置或脚本更新的工具链，必须同步保持本地 PC 助手工程目录与模拟器端的数据一致，或者将高频变动的数据完全抽离至按键精灵工作区以外的独立目录中（如 `/sdcard/FGO_Q/`）。

## 3. 安卓模拟器 (Android Emulator)

### 3.1 定位与环境
- **虚拟化运行容器**：本项目主要基于 **MuMu 模拟器（MuMu 12 / MuMu 6）**，运行 Android 操作系统与游戏本体（`com.bilibili.fatego`）。
- **ADB 宿主接口**：模拟器在宿主机暴露 ADB 调试服务端口（常见如 `127.0.0.1:5555`，设备标识形如 `emulator-5554`），自带独立 ADB 二进制程序（如 `D:\Program Files\Netease\MuMu\nx_main\adb.exe`）。

### 3.2 存储空间划分与权限
1. **公共存储空间 (`/sdcard/`，即 `/storage/emulated/0/`)**：
   - 全局可读写空间，无需复杂 Linux 提权即可通过 ADB 直接访问。
2. **按键精灵内部空间 (`/sdcard/MobileAnJian/`)**：
   - 按键精灵手机版及其 PC 助手专属空间，结构不可控，升级、清空缓存或重新打包容易受到干扰。
3. **规范化数据目录 (`/sdcard/FGO_Q/`)**：
   - 本项目专门开辟的独立存储目录；
   - 彻底脱离按键精灵的内部黑盒管理，免受 PC 助手打包覆盖干扰；
   - 作为外部配置读取与进程间总线交互的标准文件存储位置。

## 4. 模拟器中的按键精灵 (Mobile AnJian)

### 4.1 定位与系统结构
- **执行宿主 App**：安装在模拟器中的 Android 应用（`com.cyjh.mobileanjian`）。
- **底层 Root 守护进程**：按键精灵启动后会生成具有 Root 权限的守护子进程（如 `com.cxrjn.apjzj:knjpj`），获取系统底层的截屏快照、虚拟触控（Input Tap/Swipe）及物理按键注入权限。

### 4.2 两种运行方式对比

| 维度 | PC 助手维护模式 | 模拟器脱机常驻模式（APP / 悬浮球） |
| :--- | :--- | :--- |
| **触发载体** | PC 端按键精灵手机助手界面 | 模拟器内部按键精灵 APP 列表或屏幕悬浮小狮子 |
| **PC 助手依赖** | 强依赖（必须打开 PC 助手且保持连接） | 完全不依赖（平时完全无需打开 PC 助手） |
| **脚本来源** | PC 助手每次点击调试时实时打包下发 | 读取模拟器内部 `/sdcard/MobileAnJian/Script/` 留存工程 |
| **日志查看** | PC 助手底部控制台实时输出 | 网页端右下角极简日志浮层实时抓取，或直接抓取模拟器本地日志 |
| **使用频次** | **极低频**：除非修改/新增找图图片需重新打包 `.atc`，否则一般不打开 | **日常绝对核心**：日常方案切换、策略修改与全自动刷本挂机首选 |

### 4.3 核心依赖插件 (紫猫插件 `zm.lua`)
Runner 核心引擎重度依赖打包进 `.atc` 的紫猫插件（`zm.lua` / `zm.luae`），其主要赋能以下能力：
- **`zm.FindPic`**：高性能模糊找图、偏色匹配与多图并发检索；
- **`zm.DirScan`**：目录动态文件扫描与通配符过滤；
- **`zm.FileRead`**：大文本快速读取与配置字符串解析。

### 4.4 移动端运行时的技术边界与限制

在按键精灵移动端开发中，存在以下关键技术约束，决定了脚本的加载与架构设计：
1. **模块引用限制（`Import` 局限）**：
   - 按键精灵手机助手的 `Import` 语法仅支持引入打包在附件中的官方插件（如 `zm.luae`），无法直接通过 `Import` 动态加载或执行外部独立的 `.q` / `.mq` 逻辑脚本代码。
3. **字节码编译与缓存驻留机制（`MQTemp/compile.lc`）**：
   - 按键精灵手机版在执行 `.mq` 脚本前，会先将其编译为 Lua 字节码并缓存在 `/sdcard/MobileAnJian/MQTemp/compile.lc`。若脚本正处于常驻循环（如 Standby 待命）中，直接覆盖外部 `.mq` 源码文件不会触发重新编译，进程会继续执行旧字节码。
4. **函数形参静态绑定约束（不支持可选参数与重载）**：
   - 按键精灵 Q 语言在词法分析阶段对形参和实参个数进行严格的一对一校验，完全不支持默认形参值（Default Values）、可选参数（Optional Args）或同名重载（Overload）。实参与形参个数不一致会导致编译器直接拒编译。

## 5. 模拟器按键精灵日志体系与排查规范

在脚本运行与调试过程中，日志是定位逻辑停滞与异常的核心依据。按键精灵具备双重日志输出路径：

### 5.1 双通道日志输出机制
- **通道一：PC 助手调试控制台（开发首选）**：
  - **触发条件**：在 PC 助手连接模拟器并按 F5 调试时。
  - **特点**：实时回传至 PC 助手底部控制台，适合断点观察与语法告警检查。
- **通道二：模拟器本地日志文件（排查兜底）**：
  - **存储路径**：`/sdcard/com.cyjh.mobileanjian/log/`（即 `/storage/emulated/0/com.cyjh.mobileanjian/log/`）。
  - **命名格式**：`YYYY-M-D-H-M-S.log`（例如 `2026-9-25-9-58-50.log`）。
  - **生成机制**：无论是 PC 助手 F5 调试，还是模拟器悬浮窗脱机运行，按键精灵只要执行 `TracePrint`，都会实时全量落盘至该目录。
  - **编码标准**：该日志文件采用 **UTF-8** 编码，外部程序读取时必须以 UTF-8 方式解码（禁止直接用 GBK 解码，否则汉字会变为乱码）。

### 5.2 免截图直接抓取排查流程 (ADB 终端直连)
当出现“脚本没报错但逻辑没走下去/卡死/闪退”等情况时，**严禁要求用户手动截图**，应优先通过 ADB 直接翻阅模拟器日志：
```bash
# 1. 查找模拟器中最新生成的日志文件 (按时间倒序)
adb -s emulator-5554 shell ls -lt /sdcard/com.cyjh.mobileanjian/log/ | head -n 5

# 2. 读取最新一份日志的内容 (直接查看 TracePrint 输出与异常阻断信息)
adb -s emulator-5554 shell cat /sdcard/com.cyjh.mobileanjian/log/2026-9-25-9-58-50.log
```

### 5.3 模拟器日志定期清理策略
- **历史堆积隐患**：按键精灵高频调试运行时会在该目录下快速生成成百上千个小日志文件，严重拖慢模拟器文件系统索引与磁盘空间。
- **运维规范**：维护模拟器日志时，**必须保留最近 3 天的日志（例如今日及前两日）**，将 3 天以前的陈旧日志全部清除。

### 5.4 无法获取日志的典型场景与交互规范 (严禁盲猜盲改)
在某些排查阶段，系统底层**根本不会生成任何文件日志**，必须严格遵循以下判断依据与操作准则：

- **场景 A：PC 助手“检查语法 / 静态编译”阶段**
  - **PC 端无磁盘日志**：用户在 PC 助手点击“检查语法”时，由助手内置的前端解析器（`compile.lc`）执行纯内存静态词法分析。错误（如 `错误: 第115行: 参数个数不匹配。错误码=2489:66`）仅直接渲染在 PC 助手的弹窗与底部错误控件中，**绝不写入任何本地日志文件**。
  - **模拟器端完全无感知**：因为代码存在语法错误未通过编译，**脚本尚未打包，也未向模拟器下发执行**，模拟器本地日志目录 `/sdcard/com.cyjh.mobileanjian/log/` 自然没有任何新日志产生。
- **场景 B：模拟器移动端冷启动编译崩溃（Toast 报错）**
  - **移动端无磁盘运行日志**：在模拟器中点击脚本启动时，若存在参数不匹配或语法错误，脚本在编译期直接终止，根本未进入运行期，因此 `/sdcard/com.cyjh.mobileanjian/log/` **不会生成任何新日志**。
  - **Toast 调用栈快速捕获**：错误信息会通过 Android 系统的 Toast 浮窗展示并在 Logcat 中留痕，可通过 ADB 提取精准错误行号与错误码：
    ```bash
    adb -s emulator-5554 logcat -d -v time | grep "Toast callstack"
    # 输出示例: java.lang.Exception: Toast callstack! strTip=错误：第1811行：参数个数不匹配。错误码=2320:66
    ```
- **排查红线与行动规范**：
  > [!CAUTION]
  > **无日志时严禁擅自猜测与闷头改动！**
  > 当确定属于“检查语法出错”或“ADB 与本地均无日志产生”的阶段时，**外部工具或 AI 必须第一时间通过 Logcat Toast 提取错误，或主动向用户索取错误信息**（包括报错行号、错误码、提示文本或截图）。绝对禁止在没有确切证据支撑的情况下擅自臆测、盲目修改代码！

## 7. 按键精灵移动端核心避坑指南（Hard Lessons Learned）

本章节记录在实战踩坑中确认的按键精灵移动端底层限制与编码规范：

### 7.1 词法限制：严禁使用 `CLng`（必须使用 `Int` 或 `CInt`）
- **现象**：在代码中调用 `CLng(val)` 时：
  - **编译阶段**：PC 助手不仅不会提示“未定义函数”，反而在编译时抛出极其诡异的语法错误（如 `第115行: 参数个数不匹配。错误码=2489:66` 或后续变量 `名称 CurrentBattleCount 有重复。错误码=1035`）；
  - **运行阶段**：若侥幸绕过编译，移动端在执行到包含 `CLng` 的行时会立即闪退或弹出报错弹窗：`Code:115`，`Msg:_0:发生运行时错误！错误代码：2，错误行号：0，错误信息：`（底层 Lua 抛出 `attempt to call global 'CLng' (a nil value)`）；
- **根本原因**：按键精灵移动端解释器底层**未注册 `CLng` 关键字与全局函数**。当词法分析器遇到 `CLng` 时会破坏后续的语法符号栈；运行时在 Lua VM 中 `CLng` 仅为 `nil` 变量，函数调用必然引发致命运行时异常；
- **编码铁律**：在按键精灵移动端脚本中，整型转换**一律使用 `Int(...)` 或 `CInt(...)`**。十六进制或颜色判断应直接使用内置原生命令（如 `FindColor`、`CmpColor`），严禁手写带有 `CLng` 或 `&H` 字符串的算术解析。

### 7.2 空引用防护：找图循环返回 `null` 后的安全判空
- **现象**：当外部请求停止时，找图循环函数（如 `ContinuousCheckImg`）检测到停止信号后退出并返回 `null`，紧接着调用方直接执行 `Dim TapPointX = Point[1]`，导致脚本抛出空引用异常闪退；
- **防线规范**：所有接收找图坐标的地方，在访问数组下标前**必须前置判断**：
  ```vb
  Dim Point = ContinuousCheckImg(Target)
  If Point = null Or USER_STOP_REQUESTED Then
      Exit Function
  End If
  Dim TapPointX = Point[1]
  ```

### 7.3 死循环内部必须嵌入停止感知
- **原则**：所有包含 `Do While true` 的长时循环（包括开局等待 `CheckFirstBattle2Start`、选助战 `ContinuousCheckImg`、结算连续点击 `CheckNoImgAndTap2`），在循环体内部的第一行都必须显式调用：
  ```vb
  If USER_STOP_REQUESTED Or CheckStopSignal() Then
      Exit Do
  End If
  ```
  确保脚本在任何非战斗、等待或结算阶段均能毫秒级捕获停止指令，平稳退出回待命循环，绝不造成假死或卡死。

### 7.4 函数形参与实参严格匹配（严禁可选形参与同名重载）
- **现象**：当为某个既有函数（如 `CheckPriorityImg(Target, Similarity)`）扩展一个可选的偏色参数 `OffsetColor` 并将形参改为 3 个 `Function CheckPriorityImg(Target, Similarity, OffsetColor)` 后，PC 助手或移动端在启动/语法检查时立即崩溃抛错：
  `错误：第xxx行：参数个数不匹配。错误码=2320:66`
  同时脚本完全拒编译，无法启动。
- **根本原因**：按键精灵 Q 语言在词法与语法分析层面极为原始，**完全不支持默认形参值（Default Argument Values）**、**可选参数（Optional Args）** 或 **同名函数重载（Function Overloading）**。每一个自定义函数在声明时定义了几个形参，在后续所有的 `Call Func(...)` 调用点就必须且只能传入完全一致数量的实参。
- **编码与演化铁律**：
  1. **严禁修改既有基础函数的形参数量**：凡已被外部多处或广泛调用的公共基础函数，严禁随意增加或减少形参；
  2. **扩展必须采用 `Ex` 命名模式**：需要扩展参数时，必须保留原有函数签名作为标准包装器，新增 `Ex` 后缀函数承载扩展参数，例如：
     ```vb
     // 基础版本（保持 2 参数兼容既有全部调用点）
     Function CheckPriorityImg(Target, Similarity)
         CheckPriorityImg = CheckPriorityImgEx(Target, Similarity, "000000")
     End Function

     // 扩展版本（支持 3 参数偏色配置）
     Function CheckPriorityImgEx(Target, Similarity, OffsetColor)
         // 底层多图匹配实现逻辑...
     End Function
     ```
  3. **静态排查手段**：若修改了任何函数的形参列表，必须在部署前对整个源码库进行严格的全词匹配搜索，确保所有调用点的参数个数与声明 100% 对应。

### 7.5 移动端字节码编译缓存机制与热更新失效陷阱 (`compile.lc`)
- **现象**：通过 ADB 或外部工具成功将更新后的 `battle_v5_runner.mq` 推送到了模拟器 `/sdcard/MobileAnJian/Script/` 目录下，但模拟器内运行逻辑没有任何变化，抓取的运行日志依然显示旧版本的代码行号，新添加的调试输出完全不打印。
- **根本原因**：按键精灵手机版在执行 `.mq` 源码时，并不是每次都重新解析文本，而是将其编译为二进制字节码缓存在 `/sdcard/MobileAnJian/MQTemp/compile.lc`。当脚本正处于 Standby 循环或常驻待命状态时，按键精灵宿主进程持有旧字节码的内存引用与缓存，**不会自动感知或监听外部 `.mq` 文件的 mtime 变更**，依然直接复用旧的 `compile.lc` 执行。
- **部署与清理规程**：
  1. **自动化部署强制清理缓存**：任何通过外部工具（如 [editor_v5/adb_sync.py](file:///f:/2nd%20Accra/Git/Github/FGO_Q/editor_v5/adb_sync.py)）向模拟器部署 `.mq` 源码时，必须同步执行删除命令，强制销毁旧字节码：
     ```bash
     adb -s emulator-5554 shell rm -f /sdcard/MobileAnJian/MQTemp/*.lc
     ```
  2. **进程重载与热启机制**：推送新源码并删除 `.lc` 后，若旧脚本处于常驻死循环中，必须向总线写入停止信号唤出当前循环（`{"stop": true}`），促使其退出并由悬浮窗/APP重新拉起，触发底层编译器重新将 `.mq` 编译为最新的 `compile.lc`。

### 7.6 编译期与冷启动崩溃排查：Logcat Toast 异常栈秒级捕获
- **现象**：在模拟器中点击启动脚本后，屏幕闪退并一闪而过弹出一个系统 Toast 气泡，随后 `/sdcard/com.cyjh.mobileanjian/log/` 目录下**没有任何新日志生成**。外部排查人员无法从常规日志文件获取任何报错信息，极易误判为“系统未响应”或“ADB 连接失败”。
- **根本原因**：此类错误发生在按键精灵词法分析与编译期（Compile-time Crash，如上述参数不匹配、语法关键字冲突等），此时解释器尚未进入运行期，因此运行期的 `TracePrint` 日志系统根本没有被初始化，不会有任何磁盘日志落盘。但按键精灵 Android 应用在捕获到编译期 Exception 并弹出 Toast 时，会同步将异常调用栈 dump 到 Android系统的 Logcat 中。
- **秒级定位规程**：
  当遇到“启动即崩且无运行日志”时，**严禁盲猜盲改**，直接执行 ADB Logcat 过滤命令：
  ```bash
  adb -s emulator-5554 logcat -d -v time | grep "Toast callstack"
  ```
  输出示例：
  ```text
  10-18 17:05:12.345 1234 1234 W System.err: java.lang.Exception: Toast callstack! strTip=错误：第1811行：参数个数不匹配。错误码=2320:66
  ```
  该命令可瞬间捕获精确的错误行号与错误码，直接定位语法破损点。

### 7.7 数组索引体系铁律：Q 语言 `Array(...)` 严格 1-Based 原则
- **底层规则**：按键精灵移动端 Q 语言在通过 `Dim arr = Array(elem1, elem2, ...)` 声明动态数组时，**首个元素索引为 1**，即 `arr[1] = elem1`，`arr[2] = elem2`，`arr[0]` 在底层 Lua VM 中为 `nil`；
- **典型踩坑**：受常规编程语言（如 C/Python/JS）0-based 习惯影响，若在声明时习惯性垫入占位符（如 `Array(0, item1, item2, item3)` 或 `Array(Array(), item1, item2, item3)`），会导致 `item1` 实际被存放在 `arr[2]`。这会导致基于 `1..3` 下标访问（如 `heroNum = 1..3`）的逻辑整体发生 **+1 错位偏移**（从者 1 读到空占位符判定失败，从者 2 读到从者 1 的数据，从者 3 读到从者 2 的数据，原从者 3 的数据落入 `arr[4]` 被彻底丢弃）；
- **编码铁律**：Q 语言中任何由 `Array(...)` 构造的列表，首个元素必须是业务索引 1 对应的真实数据，严禁人为塞入 0 索引占位假元素。

### 7.8 全局变量必须严格前置 `Dim` 显式声明（严格 Option Explicit 机制）
- **现象**：在子程序或函数中（例如 `ReloadConfig()`）直接使用或赋值某个全局变量，但未在脚本文件顶层声明时，按键精灵移动端 MQCompiler 编译器在编译期直接报错拒编译，弹出 Toast：
  `错误：第xxx行：<VAR_NAME> 没有定义。错误号=2111`
- **根本原因**：按键精灵移动端编译器强制执行类似 Visual Basic 的严格 `Option Explicit` 变量声明规则。任何在函数内跨作用域使用的全局变量，若未在脚本顶部全局作用域通过 `Dim VarName = 0` 进行显式声明，词法分析器在符号解析时会直接将其拦截定性为“未定义全局符号（Error 2111）”并强行中断编译。
- **编码与同步铁律**：
  1. **顶层统一声明并赋初值**：任何新增的全局开关（如 `DEBUG_SCREENSHOT_ENABLE`）、手动覆盖字段（如 `MANUAL_DEBUG_SCREENSHOT_ENABLE`）或状态标记，**必须在 `Q/battle_v5_runner.q` 与 `Q/battle_v5_config.q` 文件顶部的全局变量声明区显式使用 `Dim` 声明**；
  2. **双端同步检查**：修改配置读取函数（如 `ReloadConfig`）涉及新字段时，必须严格对照顶部声明区；
  3. **静态脚本预检**：在部署脚本前可通过静态分析脚本扫描所有被赋值变量，确保它们全部已在顶层被显式 `Dim`。

### 7.9 字符串转整型必须使用 `CInt(...)` 而非 `Int(...)`
- **现象**：当直接把函数调用或字符串表达式（如 `CfgGet(...)`）嵌套传入 `Int(...)` 时，编译器抛出黄色语法警告：
  `警告：第xxx行：1个参数类型不匹配。参数类型应为浮点数型，现为子程序`
- **根本原因**：按键精灵 Q 语言中，`Int(...)` 是数学向下取整函数（Floor），其原型参数声明严格为浮点数（Float/Double）。直接传入字符串或返回未类型化 Variant 的函数表达式时，词法分析器会认为传入的是未解构的子程序或字符串，引发静态类型不匹配警告；
- **编码铁律**：读取配置或文本转为整型数值时，**统一使用 `CInt(...)` 显式转换为整型**，彻底消除编译期类型警告。
